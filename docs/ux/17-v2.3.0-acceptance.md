# UX 17: v2.3.0 acceptance, external observability

Post-implementation UX acceptance of the Observability settings dialog, metric history charts, p95 right-sizing hints and log history, at HEAD `a33cc51`. Spec: `docs/ux/16-v2.3.0-preflight.md` §2-§3 as overridden by `docs/impl/v2.3.0-tasks.md` (FZ2, §1.5 O-1..O-19; addendum > brief > UX docs) and by the tech lead's rulings in `.claude/checkpoints/feat-v2.3.0/T1-tech-lead.md`. Nobody could view the running app: everything here comes from reading the code, so each visual or assistive-technology point is in "Needs visual check" (section 4).

Reviewed: `ObservabilityDialog.tsx`, `observability.ts`, `ContextSwitcher.tsx` (summary row), `App.tsx` (palette entry, host), `MetricChart.tsx`, `metricChart.ts`, `DetailPanel.tsx` (`MetricsTab`, Containers tab), `NodeStrip.tsx`, `health/HealthShell.tsx` (`Segmented`, `PartialStrip`), `SizingHint.tsx`, `rightSizing.ts`, `LogViewer.tsx`, `LogSourceBar.tsx`, `logSource.ts`.

## Verdict

**Accepted, no must-fix.** Copy matches UX 16 and the O-rules in every string I compared. The structural contracts hold: App-level host with a modal layer, capture-phase Esc with a two-step discard, a Tab trap, focus return, `probeKey` so a Test result never outlives its target, the `Segmented` disabled-option behaviour after S2-1, the per-resource p95 fallback after M4-1, and the reverting Log source control. There are 12 should-fix items (mostly focus that drops to `<body>`, one copy defect, one preference-overwrite bug, and a few labels) and a handful of notes. None blocks the release; items S-1 to S-4 are worth landing before it because they sit on common keyboard paths.

Tokens: no colour literals in any reviewed file. Every colour is a role token (`ink`, `mute`, `bad`, `warn`, `ok`, `info`, `accent`, `metric-cpu`, `metric-mem`, `bar-*`, `surface-*`, `edge-*`, `scrim`). `ConfirmModal` is not used anywhere in v2.3.0, so `contextLabel`/`contextColor` does not apply; the dialog carries its own cluster chip (O-3). The dialog is not destructive: Save writes a per-computer record, Clear and Use only change the draft, and Cancel is the undo (a dirty Cancel or Esc asks first).

## 1. Ruling on T1 open item B-3 (forbidden line repeats its prefix)

**Ruling: strip the fixed prefix in the dialog; keep the verbatim backend text where it is a disclosure.**

The backend message for a 403 is `No access to services/proxy: {kube text}` (`observability.rs:178`, `prometheus.rs:253`; O-9 keeps that spelling because it is this app's own marker, not kube-rs wording). UX 16 §2.4 prescribes `No access to services/proxy in {ns}. {message}`, so the dialog prints "No access to services/proxy in monitoring. No access to services/proxy: services "prometheus-operated:9090" is forbidden: …". The same words twice in a row read as a bug. The "verbatim" rule (00 §9.3) protects the backend's own diagnostic text, not a prefix this app prepends to flag the case, so removing that fixed prefix does not alter what the backend said.

- **Dialog** (`probeLine`, `observability.ts:90`, and the `.catch` path at `ObservabilityDialog.tsx:314`, which stores the raw message): for `forbidden`, drop one leading `No access to services/proxy:` plus following spaces from `message`, then print `No access to services/proxy in {ns}.` and, if anything is left, a space and the remainder. Add a vitest for prefix present, prefix absent, and empty remainder (then no trailing space).
- **Metrics strip and log strip**: no change. Their sentence (`No access to services/proxy in {ns}. Showing …`) never embeds the message, and the "Why?" disclosure shows the raw message verbatim in monospace, which is its purpose.
- `isForbidden` keeps matching the prefix; only display strips it.

## 2. Findings

Severity: **must-fix** (blocks the task or is an accessibility failure), **should-fix** (friction, inconsistency, a heuristic or WCAG gap that has a cheap fix), **note** (accepted, or tracked elsewhere).

### Must-fix

None.

### Should-fix

**S-1. Dismissing the discard prompt drops focus to `<body>`.** `ObservabilityDialog.tsx:87-89` moves focus to **Keep editing** when `discard` becomes true, but when `discard` becomes false (Keep editing click, or the second Esc at `:98`) that button unmounts (`:204-216`) and focus falls to `<body>`. The Tab trap recovers on the next Tab (`:111-113`), so there is no trap, but a keyboard user loses their place and a screen reader announces nothing. Principle: WCAG 2.4.3 Focus Order, Nielsen 3 (user control). Fix: store the element focused before the prompt (`document.activeElement` when `discard` flips to true) and restore it when it flips to false; if that element is gone, focus **Cancel**. Cancel (when dirty) and the first Esc both enter the prompt, so one restore point covers both.

**S-2. "Search all namespaces" and "Show n more" unmount under the focused button.** `ObservabilityDialog.tsx:408` hides the button once `all` is true (`!all`), and `:443` hides **Show n more** after `more` is true. Both are the focused element when clicked, so focus falls to `<body>`. The preflight (§4 Focus) names Use, Retry and Save as focus cases; these two were missed. Principle: WCAG 2.4.3. Fix: after "Search all namespaces", move focus to **Find services again** (it stays mounted, `findRef`); after "Show n more", focus the first newly revealed **Use** (the row at index 8). Alternatively keep "Search all namespaces" rendered with `aria-disabled` and the helper text "Searched every namespace your account can read." once it has run.

**S-3. The dialog can return focus to `<body>` when opened from ⌘K.** `ObservabilityDialog.tsx:75` accepts any `document.activeElement instanceof HTMLElement`, and `<body>` is one. The palette is an overlay that closes before the dialog opens (UX 16 §2.1), so the opener is `<body>`; `opener?.isConnected` (`:79`) is true for `<body>`, the fallback selector is never tried, and `body.focus()` does nothing. UX 16 §2.1: "Never to `body`." Fix: `const opener = ae instanceof HTMLElement && ae !== document.body ? ae : null`. The fallback then reaches the Range radio or the panel heading when a pod panel is open; with neither present, focus the app's main landmark or the TopBar context chip (a stable target) instead of nothing.

**S-4. Copy defect: the forbidden test line repeats its prefix (B-3).** `observability.ts:90`. See section 1 for the ruling and fix.

**S-5. Two controls named "Namespace" in the Logs group.** `ObservabilityDialog.tsx:269` labels the label-name fields `namespace`, `pod`, `container` (lowercase), directly beneath the service field labelled `Namespace` (`:322`). A screen-reader user hears "Namespace, edit" twice in one group, and the lowercase visual label differs from the first only by case. Principle: WCAG 2.4.6 Headings and Labels, 3.3.2 Labels or Instructions. Fix: label them `Namespace label`, `Pod label`, `Container label` (what they are: the names of the log labels the backend filters on). Keep them `readOnly` in preset mode as now.

**S-6. The metrics tab names the wrong source when Prometheus answers with nothing.** `DetailPanel.tsx:196` defines `hist = !!target && range !== "now" && !failed`, and `:227` prints `Source: Prometheus` whenever `hist`. In the `empty` case (`:195`) the strip says "No data for this pod in Prometheus. Showing current usage only." and no chart is drawn, so the badge contradicts the strip. Principle: Nielsen 1 (visibility of system status), UX 16 §3.1 ("Source" is the data actually on screen). Fix: `hist && !empty ? "Source: Prometheus" : "Source: metrics-server · this session"`.

**S-7. Arrowing onto "Now" while Prometheus is down overwrites the remembered range.** `DetailPanel.tsx:222-224`: in the failed state the control displays `value="now"` with 1 h to 7 d disabled; arrow keys can wrap from a focused disabled option onto **Now** (`HealthShell.tsx:64-66`, which picks it because it is enabled), and `onChange` runs `setRangeState("now"); storeRange("now")`. The viewer's remembered 6 h becomes Now for every later pod, with no visible reason. This is the residue of T1 S2-1: the focus-only fix is correct, but picking the displayed value still persists it. Fix: in `MetricsTab`'s `onChange`, `if (failed && r === "now") return;` (the control already shows Now). Do the same for any caller that passes a value which is already displayed.

**S-8. Discovery errors and the partial line are not announced.** `ObservabilityDialog.tsx:421-426` (error with **Retry**) and `:427` (the `skippedLine`) render outside the polite status region at `:414`, which only carries "Found n services." and the nothing-found strings. A screen-reader user pressing Find services on a failing cluster hears nothing after "Searching…". UX 16 §4 (Live regions). Fix: put the error and partial sentences inside the status region (or give the error paragraph `role="alert"`; it is a failed user action, which §4 allows only for Save, so prefer `role="status"` and keep `alert` for Save). Keep **Retry** outside the live text so the region does not re-announce the button.

**S-9. NodeStrip control and source chip disagree when Prometheus fails.** `NodeStrip.tsx:172-175`: after every displayed node fails, the chip reads `Source: metrics-server · this session` but the segmented control still shows the chosen range checked (for example 6 h), and the reason is only in the chip's `title` (`:173`). The Metrics tab handles the same case by showing `Now` checked and disabling the rest with a reason (`DetailPanel.tsx:222-223`). The spec (UX 16 §3.3, "Failure") accepts chip text plus `title`, but §4 says the reason must not live in `title` alone, and the control must show the source on screen. Fix, minimal: when `allFailed`, pass `value="now"` and the four options a disabled reason (`HISTORY_DOWN`, shared with the Metrics tab) so the control matches the chip and the reason reaches keyboard and touch users; keep the `title` as the long message. The 60 s refetch recovers on its own; when it does, the stored range shows again. Also make the chip `role="status"` so the change is announced.

**S-10. New log-history copy renders in `text-dim`.** `LogViewer.tsx:224`: the empty state ("No log lines from Loki for this pod in the last 6 hours.") and the existing empty strings share one `text-dim` span. `dim` fails WCAG 1.4.3 as text, and this is a primary state of a new feature. Fix: `text-mute` for that span (this also covers the pre-existing "No log lines" strings in the same span, which is acceptable collateral). The codebase-wide `text-dim` items are in note N-1; this one is listed separately because the string is new.

**S-11. Small hit targets and no focus affordance on the new text buttons.** UX 16 §4 asks for at least `min-h-6` (24 px) on Range radios, Use, Test, Retry and Why?. The `Segmented` radios, Test, Use, Clear, Find and Save meet it. These do not: the metrics-tab **Retry** (`DetailPanel.tsx:236-243`) and **Why?** (`HealthShell.tsx:148`), **Configure…** in the metrics tab (`DetailPanel.tsx:260`, about 20 px) and in the log toolbar (`LogViewer.tsx:195`), the log strip **Retry** and **Why?** (`LogViewer.tsx:213`), **Reload** (`:214`), and **Show n more** (`ObservabilityDialog.tsx:444`). None sets a `focus-visible` style; they rely on the browser's default outline, which Tailwind leaves alone but `outline-hidden` utilities elsewhere in the file make easy to lose. Fix: add `min-h-6 px-2 rounded-sm focus-visible:ring-2 focus-visible:ring-accent/60` (the class set `ContextSwitcher.tsx:182` already uses) to each. `PartialStrip`'s toggle is shared with Health; adding `min-h-6 px-1.5` there is harmless and fixes the Health pages too.

**S-12. The save announcement is silent the second time.** `ObservabilityDialog.tsx:38` sets the polite string `Observability settings saved for {label}.` to a constant; a second save for the same cluster sets the same state value, the DOM text does not change, and nothing is announced. Fix: clear it when the host opens a dialog (inside the request listener at `:29`, `setAnnounce("")`), or append a changing zero-width token. One line.

### Notes (accepted or tracked elsewhere)

**N-1. Pre-existing `text-dim` as text, codebase-wide (not a v2.3.0 blocker).** `ObservabilityDialog.tsx:19` (the `placeholder:text-dim` on "optional", a 1.4.3 failure for placeholder text) and `:319` (group heading, 9.5 px); `ContextSwitcher.tsx:175`; `SizingHint.tsx:16` (`quiet`, the "Hints need metrics-server…" and "Collecting samples" lines, which pre-date v2.3.0); `NodeStrip.tsx` labels and counts; `LogSourceBar.tsx:69-70`; `LogViewer.tsx:206,209,221,227`; `DetailPanel.tsx:314`. T1 already recorded the pattern (84 uppercase section labels). One token change (`--c-dim` lighter in the dark theme, darker in the light one) would close them all; that is a separate task. In the light theme `dim` is `122 131 151` on white (about 3.8:1), so it fails there too.

**N-2. Accepted deviations (T1 rulings): no finding.** NodeStrip range is local state, default Now, not persisted (FZ2 F2 over UX 16 §3.1); failure shown as chip text plus `title` with no strip (UX 16 §3.3 "Failure" row, modulo S-9); MetricsTab builds cards from series labels when metrics-server is down; p95 hints omit the "samples are taken by this app" tooltip; the `refetchInterval` is `max(60 s, step)`.

**N-3. Keyboard order of discovery vs 06 §9.2.** The code places **Search all namespaces** immediately after **Find services** (`:408`), before the suggestion list; 06 §9.2 lists it after the suggestions ("Use, then Search all namespaces"). The code order is arguably better (the control that changes what you are about to read comes first), and nothing is trapped or skipped. Keep, and update 06 §9.2 in the docs pass.

**N-4. `Test` disabled reason is generic when the cause is another field.** `ObservabilityDialog.tsx:302`: when only Path prefix or Tenant is invalid, Test says "Fill in namespace, service and port first." although those are filled. The Save reason ("Fix the highlighted fields.") is right. Polish: use `Fix the highlighted fields.` when `Object.keys(errors).length > 0` and the group is not unset.

**N-5. Two buttons named "Test" and two named "Clear" in one dialog.** Each sits inside a `role="group"` named by its heading (`:318`), so a screen reader that announces group names on entry disambiguates them. Polish: `aria-label={`Test ${title}`}` / `Clear ${title}` costs nothing.

**N-6. Dialog accessible name omits the cluster.** `aria-labelledby` points at "Observability" only; the cluster chip follows the heading but is not in the name. Polish: add the chip's id to `aria-labelledby`, so the name reads "Observability prod-eu".

**N-7. Segmented has no Home/End.** `HealthShell.tsx:56-67` handles arrows only. Native radio groups also support Home/End, but the APG radio pattern does not require them. Not blocking; the five-option groups are short.

**N-8. Titles that carry information.** `NodeStrip.tsx:86,97` (`NO_ALLOC` on the sparkline wrapper) and `:173` hold their text in `title` only. The preflight accepted the allocatable note as a `title` because the percentage beside the sparkline is the real alternative; flagged only so nobody builds on it. A failed-source reason must not rely on `title` (S-9).

**N-9. Status-region mounting.** `PartialStrip` with `live` renders `role="status"` already containing its text (`DetailPanel.tsx:230`). Some screen readers do not announce a region that is inserted with its content; it works reliably only when the region exists first and its text changes. Listed under "Needs visual check" because only a real screen reader settles it. If it fails, render an empty `role="status"` wrapper permanently in `MetricsTab` and mount the strip inside it.

### Keyboard, focus and roles

- **Esc layering.** `useModalLayer(true)`; the capture-phase handler acts only when `isTopmost()`, calls `stopPropagation`, and handles Esc inside inputs and selects (preflight §2.1). Clean closes; dirty asks; a second Esc is Keep editing, never Discard. The switcher stays open underneath (not a layer) and its input's own Esc does not fire because focus is in the dialog.
- **Tab trap.** Wraps first/last, pulls back focus that lands outside (`focusin`), skips hidden controls, keeps `aria-disabled` and `readOnly` controls reachable (correct for the reason text and for read-only preset labels).
- **Initial focus** is Find services (rAF). **Return**: the opener, else the checked Range radio, else the panel heading, with the `<body>` hole in S-3. Opened from IdentityEditor, the opener is **Configure…** inside the still-mounted switcher, which works.
- **Roles and labels.** `role="dialog"`, `aria-modal`, `aria-labelledby`; each group `role="group"` with `aria-labelledby`; every input has a visible `<label>`; errors use `aria-invalid` and `aria-describedby`; Backend and Scheme are `radiogroup`s of native radios; the Test line and the discovery count are polite `role="status"`; only a failed Save is `role="alert"`.
- **Segmented after S2-1.** Verified by reading: arrows move one step and never skip; stepping onto a disabled option focuses it without picking (its reason is read from `aria-describedby`); a click on a disabled option bails out; disabled options are not tab stops (only the checked radio is), consistent with a roving group. One residue is S-7.
- **Save.** `aria-disabled` plus visible reason (`disabledAttrs`), still clickable so a failed Save focuses the first invalid field and reveals all errors (UX 16 §2.3).
- **Chart.** `role="img"` with the full numeric alternative, repeated as visible text, so colour is never the only carrier (1.1.1, 1.4.1). Stroke tokens `metric-cpu` / `metric-mem` against `surface-card` are well above 3:1 in the dark theme (about 6 to 7:1); in the light theme the two strokes are about 3.9:1 against white, which still meets 1.4.11 for a graphical object.

## 4. Needs visual check (for the user, in the running window)

Nobody could view the app. Please look at these, in this order of risk:

1. **Dialog at a small window.** Open at 720 px height and at about 800 px width: header and footer pinned, body scrolls, nothing clipped. The three-column grids (Namespace/Service/Port, then Scheme/Path prefix/Tenant) are `grid-cols-3` with no responsive step: check the label `Tenant (X-Scope-OrgID)` and its helper do not overflow a one-third column, and that the new S-5 labels (`Namespace label`, `Container label`) fit.

6. **Information strip.** `bg-info/10` with `ring-info/30`, the **Retry** and **Why?** buttons at 320 px (does the sentence leave room?), the open **Why?** list in monospace with long backend text wrapping.
