## 2. Findings

Severity: **must-fix** (blocks the task or is an accessibility failure with no cheap workaround), **should-fix** (friction, inconsistency, a heuristic or WCAG gap with a cheap fix), **note** (accepted, or tracked elsewhere).

### Must-fix

None.

### Should-fix

**S-1. Helm Values: Reveal and Hide values drop focus to the document.** The Reveal/Hide toggle is rendered inside `<YamlFind key={`${idKey}\u0000${helmRevealedNow}`}>` (`ResourceDetailPanel.tsx`:3491, toggle at :3554-3565). `helmRevealedNow` flips to true when the revealed text arrives and back to false on Hide, so React unmounts the whole find subtree, including the button the user just activated. Nothing restores focus (no `.focus(` call exists in the file). Before v2.3.1 the toggle was one element in a fixed place and kept focus; that was a specified contract: `docs/ux/04-health-capacity-rbac.md`:1522 ("After a reveal, focus stays on the same control, whose label changes to Hide values. After Hide values, focus returns to Reveal values") and finding FIX-3 of `docs/ux/08-v1.4.1-acceptance.md`, which the old comment at the toolbar still cites ("the toggle keeps its place, so focus stays on it (04 6.2)"). The polite "Values revealed." and "Values hidden." line is in the panel root, so it still speaks, but a keyboard user loses their place (WCAG 2.4.3 Focus Order; Nielsen 3, user control). The same remount happens for "Reveal and edit…".
Fix (owner `src/components/ResourceDetailPanel.tsx`, and `YamlFind.tsx` if option b is taken). Any one of:
- (a) smallest: give the toggle `data-helm-toggle` and, in the panel root, an effect keyed on `helmRevealedNow` that, after the transition (not on first mount), focuses the toggle when `document.activeElement` is `document.body` or null. Children commit before the parent effect, so the new button exists.
- (b) keep S2 strict without a React key: replace the key with a `resetKey` prop on `YamlFind` that resets query, open state and navigation during render when it changes (the derived-state pattern), so the toggle element survives and the query is cleared before the next paint.
- (c) hoist the toggle, the "Revealed" chip and the redaction note out of the keyed subtree and give `YamlFind` only the find button and content; costs a layout change in the toolbar row.
Re-check by keyboard: Tab to Reveal values, Enter, wait for the values, focus must still be on the button (label Hide values); Enter again, focus on Reveal values. No unit test is possible (Vitest runs in the node environment).

**S-2. The Kinds button's accessible name does not contain its visible text.** With kinds hidden the button shows "Kinds · 2 hidden" but is named "Kinds to show, 2 hidden" (`MapPage.tsx`:124). The visible words are not a contiguous part of the name, which fails WCAG 2.5.3 Label in Name (Level A) for speech-control users ("click Kinds 2 hidden"). With nothing hidden the name "Kinds to show, all shown" does contain "Kinds", so only the hidden state fails. The wording comes from UX 22 §3.4 and §3.12, so this is a spec defect that the implementation followed. Fix (owner `src/components/health/MapPage.tsx`:124): drop the `aria-label` (the visible text is already a good name and `aria-haspopup`/`aria-expanded` carry the rest), or name it "Kinds, 2 hidden" and "Kinds, all shown". If taken, this document supersedes the UX 22 §3.4 and §3.12 name.

### Notes

**N-1. Wireframe versus chip text.** UX 22 §3.3 shows "[Config 0]" after ConfigMaps are hidden. The code shows the group total (8) for a group with nothing visible, which is what §3.2 means by "not pressed (as today)" (`MapPage.tsx`:112). Keep the code; the wireframe was a slip.

**N-2. Match line period.** With nothing hidden the line now reads "3 matches." (was "3 matches"). UX 22 §3.7 said the old copy is unchanged; the plan's `matchLineText` contract (§3.2) wins and TL-R accepted it. Cosmetic.

**N-3. Esc on the YAML text closes the panel when the bar is closed.** The read `<pre>` is now focusable (the F8 fix), and the existing App rule closes the detail panel on Esc from a non-editable target (`App.tsx`:535-552). UX 22 §5.1 specifies exactly this, and with the bar open the bar takes Esc first. Listed so the user sees it in the visual check (section 5, item 11); it is not a defect.

**N-4. Hidden-link count when Pods are hidden.** `groupOf` is built from the prepared nodes (`MapPage.tsx`:221-225). When the Pods kind is hidden the pod groups are not in the prepared map, so a shown ReplicaSet counts each of its pods as its own hidden link (for example "12 connections go to hidden kinds") where a visible group would count 1. The sentence is true, only noisier. Upgrade path: build `groupOf` from `groupPods` of the narrowed set. Not a blocker.

**N-5. Identical status strings are not re-announced.** The find's live region and the map announcement set a state string; when the next message is identical (for example stepping through a single match, "1 of 1, wrapped" each time) the DOM text does not change and nothing is spoken. Same family as S-12 of UX 17. Harmless here because the position cannot change.

**N-6. C-6 reset on the first Neat load.** Accepted in the plan: switching Neat on for the first time shows the skeleton and resets the bar. Not a regression (the skeleton already replaced the toolbar before v2.3.1).
