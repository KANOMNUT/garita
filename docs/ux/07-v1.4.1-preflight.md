### P1. The #33 headline property is false as worded; tech lead must choose the mechanism (blocks)

- **Surface:** #33, 3.15, 4.13, 5.11, 9.1 item 1.
- **04 assumes:** reveal is the only door ("Nothing has been fetched" before Reveal, §2.7 step 1). It never lists the other readers of the whole object.
- **Shipped/brief:** `get_resource_json` and `get_resource_yaml` return the full Secret to any caller (`useResources.ts:606-613`, `:574-581`). Four callers besides the reveal hook fetch it: Field managers (d), Compare (e), the editor (c), the YAML tab (b). Brief §2.1's acceptance grep (`\.data\b` on Secret-typed values) cannot see them, and live row 1 ("revealed query is gone after close") would pass while `["resource-json","sec",...]` still holds the values.
- **Resolution, pick one:**
  - **A (root cause):** `get_resource_json`, `get_resource_yaml`, `get_resource_yaml_neat` take `reveal: Option<bool>`. For `sec` without `Some(true)` the backend drops `data`/`stringData` values (keeps keys). Field managers and Compare then work without values; the reveal hook, editor and YAML tab pass `reveal: true`. Compare of two Secrets would compare keys only and say so. Property stays literally true. Touches 3 to 4 Rust commands and the merge-preview `live` (P2).
  - **B (recommended for v1.4.1):** keep the commands as they are and state the property honestly: "no Secret value is displayed without a per-object reveal, and none is kept in the webview after the panel (or dialog) closes". Enforce with P2 (mask merge preview), P3 (`gcTime: 0` plus removal for every Secret read), and the paths table above. Record A in `open-items.md` as the strict follow-up.
  - Either way the R6.6 `CLAUDE.md` hard-rule sentence and the §2.1 acceptance grep must be reworded to match the chosen option before F1 merges.
- **Severity:** blocks (F1 acceptance and the CLAUDE.md line depend on it).

### P2. Merge from file shows live Secret values unmasked (blocks)

- **Surface:** #33 (not in 04; 04 §8 checks YAML Save and Compare only).
- **Shipped:** `mergePreview.ts:83-92` emits `from: stringify(liveChild)` and `state: "unchanged"` rows with the live value; `MergeFromFileModal.tsx:50` renders them with no `maskSecretData`. Reuse `diffRows.ts` masking so there is one rule. Add a test beside `mergePreview` (the file has no test today). Optional hardening for R4-scope Rust: blank `live` values for `Secret` in `preview_yaml_documents`.
- **Severity:** blocks. Ship in the F1 commit (it is a #33 path).

### P3. Secret reads outlive the panel: `gcTime` and removal must cover every Secret query, not only `["secret-reveal"]` (blocks)

- **Surface:** T41-2, 9.1 item 1, Q17.
- **Shipped:** `useResourceYaml` (`useResources.ts:574`), `useResourceYamlNeat` (`:589`) and `useResourceJson` (`:606`) use React Query's default 5 min `gcTime`. Brief §2.1 sets `gcTime: 0` only on the new `["secret-reveal", ...]` key.
- **Resolution:** for `kind === "sec"` all three set `gcTime: 0`, and the panel/dialog close handler (and selected-object change, context switch, namespace change) calls `removeQueries` for `["secret-reveal"]`, `["resource-json","sec"]`, `["resource-yaml","sec"]` and `["resource-yaml","neat","sec"]`. The reveal hook lives in the panel root (`ResourceDetailPanel`), never in a tab body, so it keeps an observer while the user switches tabs (an unobserved `gcTime: 0` query is dropped at once, which would silently end the "persists across tabs" rule). Selection identity for "selected object changed" is `(context, namespace, name)`, not `name` alone.
- **Severity:** blocks (the live check and the lifetime promise in the UI footer are false otherwise).

### P16. Helm redaction is key-based, so the "redacted" view is not a safe-to-share view (should, copy)
