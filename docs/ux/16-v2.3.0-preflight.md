No new colour is needed. `IdentityEditor` copies `text-dim` for its 9.5 px group headings and its 10.5 px descriptions; **do not copy them** (WCAG 1.4.3, `dim` fails as text). ### 2.2 Storage

- `IdentityPatch` gains `observability?: Observability | null` (`null` deletes the key, so Clear on both groups leaves a record without the field, not `{}`).
- `writeStore` must report failure. Save then keeps the dialog open and shows, in the footer `role="alert"`: `Couldn't save the settings on this computer.` Success closes the dialog and announces through a polite live region at the host: `Observability settings saved for {cluster label}.`
- Read side: a non-object or wrongly-shaped `observability` reads as unset **without** raising the store-corrupt note (that note means the whole record is unreadable). A target missing namespace, service or port reads as unset for that half.
- The store is `localStorage`: per install, not synced, not exported. Say so once, as footer helper text left of Cancel: `Saved on this computer.`

### 2.3 Dialog fields and validation (verbatim)

A group is **unset** when namespace, service and port are all empty; **invalid** when only some are filled. Clear empties a group.

| Field | Rule | Error text |
|---|---|---|
| Namespace, Service | DNS-1123 label, 1 to 63 characters | `Use lowercase letters, digits and "-".` |
| Port | 1 to 65535, or a port name (lowercase, digits, "-", at most 15 characters) | `Enter a port number (1 to 65535) or a port name.` |
| Path prefix | empty, or starts with `/` and has no `..` segment | `Path prefix must start with "/" and must not contain "..".` |
| Custom label names | non-empty; letters, digits, `_`, `.`, `:`, `-` (VictoriaLogs names contain dots) | `Enter a label name.` |

§6.3 wrote the prefix error as `…can't contain ..` ending in `..`; that reads as a typo. Use the text above. Validation runs on blur and on Save. Save disabled reason (via `disabledAttrs`): `Fix the highlighted fields.` On a failed Save click, focus the first invalid field. Every input has a visible `<label>`; errors use `aria-invalid` and `aria-describedby`. Each group is `role="group"` with `aria-labelledby` on its heading.

### 2.4 Test

- Tests the **draft**, not the saved record. Editing any field of a group clears that group's result (else "Reachable" stays on screen for a different service).
- Disabled until the group is valid: `aria-disabled` with `Fill in namespace, service and port first.`
- Result names what was tested. Lines (replace §6.5; "Prometheus" becomes `{Flavour}`: Prometheus, Loki, VictoriaLogs):

| `state` | Line |
|---|---|
| ok | `Reachable: {ns}/{service}:{port}.` then ` {Flavour} {version}.` only when `version` is present (Loki and VictoriaLogs may return none) |
| unreachable | `Couldn't reach the service. Check the namespace, service and port. {message}` |
| forbidden | `No access to services/proxy in {ns}. {message}` |
| wrong service | `The service answered, but it doesn't look like {Flavour}. Check the port and path prefix.` |
| testing | `Testing…` (spinner; Test `aria-disabled`) |

One `role="status"` per group. `{message}` is the backend text verbatim (00 §9.3). The words carry the meaning; the glyph is decorative.

### 2.5 Permission hint: correction to my §6.4

§6.4 disabled Test on an explicit `can_i` deny. That is wrong in practice: `AccessCheck` has no `name`, and a Role granting `services/proxy` with `resourceNames: ["prometheus-operated"]` is a normal least-privilege setup; an unnamed SSAR answers `allowed: false` for it. Disabling Test would block exactly the users the hint is for. **Test is never disabled by the permission hint** (D6). The hint stays a HINT-ROW:

- default: `Hint: needs permission to get services/proxy in {ns}.`
- explicit deny: `Hint: your account may not be allowed to read through the service proxy in {ns}. Test shows the real result.`

The check runs when the namespace field blurs (not per keystroke: the query key embeds the whole `checks` array, so typing would fire one SSAR per character), fails open, and uses the dialog's `context`.

### 2.6 Discovery

| State | Spec |
|---|---|
| Idle | No automatic search on open: opening a dialog must not make cluster calls the user did not ask for. **Find services** is the first control. |

| Several | Operator, k8s and thanos Prometheus services are all listed; none preselected. The row text states which port the backend chose (it must be in `reason`; the user can edit). |
| Many | Cap the list at 8 rows with `Show {n} more`. |
| Nothing found | §6.7 strings, unchanged. |
| Partial | `Couldn't list Services in {namespaces} ({reason}). The list may be incomplete.` (skipped-source shape; D2) |

### 2.7 Switching Backend and presets

Choosing the other backend sets the preset to that flavour's preset **unless Custom is selected**. The three Custom values stay in the draft when switching away, so a mistaken click loses nothing. Preset label fields are visible and read-only (`readOnly`, not `disabled`, so they stay in the tab order and readable).

**Range control.** `Segmented` with an added optional per-option `disabledReason` (rendered with `disabledAttrs`; the radio stays focusable, click and arrow-selection bail out). Options `Now`, `1 h`, `6 h`, `24 h`, `7 d`; `Now` is metrics-server and is the default only when Prometheus is not usable.

| Prometheus | Control | Below |
|---|---|---|
| Not configured | none | `Source: metrics-server · this session` and `History beyond this session needs Prometheus. Not set for this cluster.` with **Configure…** (not dismissible, one line, no badge) |
| Configured, working | five options | `Source: Prometheus` (or `metrics-server · this session` when Now) |
| Configured, unreachable | `Now` enabled, the four others disabled, reason `History needs Prometheus, which isn't reachable right now.` | fallback strip (3.2) |
| Configured, forbidden | same as unreachable | fallback strip, forbidden text |

When both sources fail (metrics-server error and Prometheus failure), the existing warn line `Metrics server unavailable — showing resource requests` stays as is and the information strip sits above it: two independent notes, never merged into one sentence.

### 3.2 Fallback strip

Generalise `PartialStrip` (props `toggleLabel`, optional `actions` node) rather than add a third strip; keep `StaleStrip` for its own "couldn't refresh" meaning. Tokens as `PartialStrip`: `bg-info/10 ring-1 ring-info/30`, `Info` glyph in `text-info`, text `text-ink`. `role="status"` (polite, not `alert`: it is information) so a background refetch that replaces the chart is not silent to a screen reader. Buttons **Retry** and **Why?** (`aria-expanded`; the disclosure shows the backend message verbatim, monospace, `break-words`).

| Case | Text |
|---|---|
| Unreachable | `Prometheus unavailable, showing current usage only.` |
| Forbidden | `No access to services/proxy in {ns}. Showing current usage only.` |
| Empty | `No data for this pod in Prometheus. Showing current usage only.` |

**Retry** refetches and shows `Retrying…` in place of its label, `aria-disabled`. If the retry succeeds the strip unmounts under the user's focus: move focus to the Range group's checked radio. If it fails, keep focus on Retry.

### 3.3 NodeStrip (F2, node half)

| Part | Spec |
|---|---|
| Control | One compact `Segmented` and the source chip in the strip header, between the title and "View all", **only when Prometheus is configured and not known unreachable**. Default `Now`: the 20-sample session buffer and the current percent sparklines are unchanged, and the overview does not start making Prometheus calls on load. Choosing 1 h to 7 d loads `node-cpu` and `node-mem` for the displayed nodes (at most 6, so 12 parallel calls; acceptable). |
| Units | The bar and sparkline are **percent of allocatable** (`nodes.rs`). The templates return millicores and MiB. Convert in the strip with `NodeCapacity.cpu_allocatable_m` and `mem_allocatable_mi` (already passed as `capacity`), clamp to 100 as the backend does. No allocatable for a node: that node keeps its session sparkline and its `title` says `Node capacity isn't available, so history can't be shown as a percentage.` No Rust change (D8). |
| Sparkline | Keep `Sparkline` at 48 x 16 (`aria-hidden` is acceptable here because the percent beside it is the text alternative). |
| Failure | No strip on the overview: the sparklines fall back to the session buffer and the chip reads `Source: metrics-server · this session`; the reason is in the chip's `title`. The full wording lives on the Metrics tab. |

### 3.4 Right-sizing hints (F3, #13+)

| Part | Spec |
|---|---|
| Where | Containers tab (`SizingHint`), per container. Query `container-p95-cpu` and `container-p95-mem` only when that tab is open and Prometheus is configured. Failure or empty is silent here: the hint falls back to today's session-based result unchanged, tail `Based on current usage only.` (no strip on this tab; the source is named by the tail). |
| Coverage | A p95 may be claimed "over 24 hours" only when the series covers at least about 18 of the 24 hours (75 percent of the samples). A container started 2 hours ago gets the session path. This needs a coverage value from the backend (D3). |
| Rules | With a p95: undersized when p95 is at least 90 percent of the container's own limit; oversized when p95 is under 25 percent of its own request. Same constants (`RIGHT_SIZING`), same "own request and limit only, never the pod fallback" rule, no suggested value. The 10-sample minimum applies to the session path only; Prometheus coverage replaces it. |
| Sentences | Separate from the session ones (the old ones say "peak" and "last N samples", both false for a percentile). Undersized: `{Name}'s 95th percentile reached {pct}% of its limit ({v}{u} of {limit}{u}).` plus ` It may be throttled.` for CPU only. Oversized: `{Name}'s 95th percentile stayed under 25% of its request ({v}{u}, request {request}{u}). The request may be larger than needed.` Tail: `Based on the 95th percentile over 24 hours.` The `Hint` label stays. |
| Metrics-server absent | `Hints need metrics-server, which isn't installed on this cluster.` shows only when no p95 is available either. With a usable p95, hints render and the tail names the source. A p95 below the hint thresholds shows no hint (no "all good" line, as today). |
| Honesty | A percentile hides short spikes; it must not be worded as OOM or throttling certainty. "May" wording stays; no score, no grade. |
