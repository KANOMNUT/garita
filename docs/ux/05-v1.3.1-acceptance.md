## Findings

### Must-fix

#### UXA-1 (F2) must-fix: the line count is a polite live region that fires on every streamed line

Evidence. `LogViewBar.tsx:156`: `<span role="status" aria-live="polite" ...>{countText(lines.length, ...)}</span>`. `lines` grows on every rAF flush while following, so the text changes continuously and a screen reader announces "412 lines", "431 lines", and so on without end. Violates 02 section 6.3 ("Filter changes: the count line is a polite status ... debounced so typing doesn't spam"; streaming status "at most one announcement per 5 seconds", A11Y 10.4). The sr-only regions in the viewers (`LogViewer.tsx:161`, `MultiLogViewer.tsx:150`) are fine: they change only on state changes.

Fix. Remove `role="status"` and `aria-live` from the visible count span (keep it as plain text). Add one sr-only `role="status" aria-live="polite"` inside `LogViewBar` whose text is `countText(...)` taken from a value updated only when `view` (Include, Exclude, levels) changes, debounced 800 ms, and not when `lines` changes. While streaming with no filter active it announces nothing.

#### UXA-2 (F7) must-fix: "Keep waiting" does the opposite of waiting

Evidence. `ShellTab.tsx:153`: `<button ... onClick={dbg.stopWaitingNow}>Keep waiting</button>`, the same handler as "Stop waiting" (`:143`). `useDebugSession.ts:99,137` shows `stopWaiting` suppresses auto-attach and makes the strip render "Stopped waiting. {name} is still being added to this pod." with an Attach button (`ShellTab.tsx:160-164`). 02 section 2.4 step 9 and section 5.4: in the pull-failing state "Keep waiting" keeps polling and leaves the strip as it is; "Stop waiting" is the separate control.

Fix. Add `keepWaiting: boolean` state to `useDebugSession` (reset in `started`, `clear` and the pod-change effect) with `keepWaitingNow = () => setKeepWaiting(true)`. In `ShellTab`, show the pull-failing `Card` only while `!dbg.keepWaiting`; "Keep waiting" calls `dbg.keepWaitingNow`. The strip line keeps showing `pullFailingText(card)`. "Stop waiting" keeps `stopWaitingNow`. If the container later reaches `running` while `keepWaiting` is set, auto-attach proceeds as normal.

#### UXA-3 (F7) must-fix: the debug dialog opens with the irreversible primary focused

Evidence. `DebugContainerDialog.tsx:75-80` passes no `initialFocus`; the dialog is non-destructive with no typed field, so `ConfirmModal.tsx:203` picks `"primary"` and focuses "Start debug container". 02 section 6.2: "initial focus on the Image field since it is the first required input". The action adds a container that cannot be removed (`02` section 3.8); one stray Enter or Space on open performs it before the user has read the image or target.

Fix. Add `initialFocus?: "cancel" | "primary" | "input" | "first"` handling to `ConfirmModal`: `"first"` focuses `card.querySelector("[data-modal-initial]") ?? first FOCUSABLE inside the body`. In the dialog, set `initialFocus="first"` and `data-modal-initial` on the `#debug-image` input. Check live that `requestAnimationFrame` focus lands after the input mounts.

### Should-fix

#### UXA-4 (F2) should-fix: the filtered-empty state has no "Clear filters" button

Evidence. `LogViewer.tsx:172` and `MultiLogViewer.tsx:167` render only `filteredEmptyText(lines.length)` as plain text. 02 section 2.2 step 7 and UXP-10 (adopted): "...offers Clear filters". The strip's "Clear all" exists only while a chip is showing, and Include (not a chip) can be the sole filter.

Fix. After the text, render `<button type="button" onClick={() => onViewChange((v) => clearFilters(v))} className="ml-2 text-accent hover:underline">Clear filters</button>` in both viewers (import `clearFilters` from `utils/logFilter`).

#### UXA-5 (F2) should-fix: Include and Highlight marks disappear in JSON summary rows

Evidence. `LogLine.tsx:80-81`: in summary mode the message slice is passed `inc={summary.message ? [] : inc}` and `hl={summary.message ? [] : hl}`, and the key=value fields are plain text. The line was kept by a match on `body` and counted in "Match 3 of 17", but the user sees no mark, and Enter scrolls to a row with nothing highlighted. 02 section 6.4: Highlight is a tint plus underline; a counted match must be visible.

Fix. In summary mode, when `inc` or `hl` has ranges and none of them fall inside the displayed message or fields, render the row expanded (as if `expanded` were true) so the raw JSON with marks is shown, and add the chevron state "Collapse JSON". Simpler acceptable alternative: in summary mode, find ranges on the summary text itself (`message` and each `key=value` string) instead of on `body`, using `findRanges(text, include)` per piece.

#### UXA-6 (F2) should-fix: narrowing to zero pods leaves the previous lines on screen

Evidence. `MultiLogViewer.tsx:80`: `if (!selectedContainer || !podsKey) { setPodStreams({}); return; }` returns before `clear()` (`:81`). Streams stop through the effect cleanup, but `lines` keeps the earlier narrowing's output, so the log region shows "No pods match node x." followed by stale lines (`:156-168`). The same happens when `selectedContainer` becomes "" (`:75`).

Fix. In that branch call `seqRef.current = 0; clear(); setExpanded([]); setActiveMatch(null); setReloading(false);` before returning.

#### UXA-7 (F2) should-fix: the Pods popover omits three things the spec and Q-L5 require

Evidence. `MultiLogViewer.tsx:145`. (a) With no zone labels the Zone select is simply not rendered (`zonesAvailable &&`), with no explanation; brief section 1.3 Q-L5 says the popover says "This cluster has no zone labels." (b) Rows show tag and node only (`placement.get(pod.name)?.node ?? "unknown"`); 02 section 3.7 wireframe shows node, zone and "120 lines". (c) "unknown" has no tooltip (02 section 5.2: "Watchtower couldn't read this label.").

Fix. (a) When `!zonesAvailable`, render `<p className="text-[10.5px] text-dim">This cluster has no zone labels.</p>` in place of the select. (b) Each row's right text becomes `{node} · {zone} · {count} lines` (count = `lines.filter((l) => l.pod === pod.name).length`, memoised), keeping the existing " · ended" / " · couldn't be tailed" suffix. (c) Wrap "unknown" in `<span title="Watchtower couldn't read this label.">`.

#### UXA-8 (F4) should-fix: disabled reasons rely on `aria-description`

Evidence. `utils/guardrails.ts:126-131` (`disabledAttrs`), `GenericResourceTable.tsx:293`, `SettingsView.tsx:102` set `aria-description`. That attribute is an ARIA 1.3 draft: Chromium (WebView2) exposes it, but the macOS build runs in WKWebView and Linux in WebKitGTK, where support is not guaranteed. 03 section 11.4 and 00 DISABLE-PRECEDENCE specify `aria-disabled` plus a described-by reason. If the engine ignores it, the reason is available only as a hover tooltip, which a keyboard or screen-reader user never gets.

Fix. Change `disabledAttrs` to return `{ "aria-disabled": true, "aria-describedby": id, title }` where `id` comes from a `useId()` the caller passes in, and have callers render `<span id={id} className="sr-only">{reason}</span>` beside the control. The cheaper uniform route: add a tiny `<DisabledReason id reason />` helper and make `disabledAttrs(reason, id)` require the id. Keep `title` as is. Update `guardrails.test.ts:109`.

#### UXA-9 (F4) should-fix: the Read-only description in the IdentityEditor contradicts the shell decision

Evidence. `ContextSwitcher.tsx:121`: "...Actions already running aren't stopped." Brief section 0.5 (user decision): turning read-only on ends every open shell or attach session for that cluster. The text a user reads when switching the mode on says the opposite for the one action the decision does stop.

Fix. Replace the last sentence with: "Open pod shells for this cluster end. Other actions already running aren't stopped." (Keep it to one sentence under the label.) Also fix the stale comment at `utils/guardrails.ts:11` ("pending user confirmation" is now confirmed).

#### UXA-10 (F5) should-fix: a drain finished with force-deleted pods is shown as a clean success

Evidence. `NodeDrainDialog.tsx:663` (`icon = outcome === "complete" ? <CheckCircle2 ... text-ok>`) and `:808` (`tone = outcome === "complete" ? "ok" ...`) ignore `counts.forced`. 01 section 2.9 table: "Complete with forced" uses the `status-warn` role; UXP-22 (adopted) asked for the warn tone. The title already says "Node drained, 2 pods force-deleted", but a green check and green card border signal "nothing to look at".

Fix. At both places use `outcome === "complete" && counts.forced === 0` for the ok variant. When `counts.forced > 0`, use `<AlertTriangle size={16} className="text-warn shrink-0" />` and tone `"warn"`.

#### UXA-11 (F6) should-fix: two Sidebar items look active while Settings is open

Evidence. `App.tsx:304` still passes `active={activeResource}`, so the previously selected resource keeps its highlight while `settingsActive` also highlights the gear (`Sidebar.tsx:354-356`). 00 section 7.1: "The Sidebar nav highlights the gear."

Fix. Pass `active={mainView === "settings" ? ("" as ResourceType) : activeResource}` (or add an `inactive` prop) so no nav row is highlighted in Settings. The resource view stays mounted and hidden as it is now.

#### UXA-12 (F7) should-fix: debug progress and failures are not announced

Evidence. `ShellTab.tsx:45-63` (`Strip`) has `aria-current="step"` but no live region. `Card` (`:36-43`) is `role="status"` for every tone, including "This pod no longer exists" and "Connection lost" (`:112`, `:190`). 02 section 6.3: "current step announced politely; failures assertively". Cards that mount already filled are often not announced as live insertions.

Fix. In `Strip`, wrap the status line in `<div role="status" aria-live="polite" aria-atomic="true">` and make its text change only on a step or reason change (do not put the per-second `waitingText(seconds, ...)` in it; render the seconds in an `aria-hidden` span). In `Card`, use `role={tone === "bad" ? "alert" : "status"}`.

#### UXA-13 (F7) should-fix: focus does not move to the progress strip after the debug dialog closes

Evidence. `DebugContainerDialog` closes through `onStarted` (`DetailPanel` `dbg.started`). `ConfirmModal.tsx:216-218` returns focus to the opener ("Debug container…"). 02 section 6.2: "After the dialog closes into the Shell tab, focus moves to the status strip heading so the progress is announced in context." Nothing in `ShellTab.tsx` takes focus.

Fix. Give `Strip`'s `<ol>` container `tabIndex={-1}` and a ref; in `ShellTab`, run an effect keyed on `session?.name` that calls `ref.current?.focus()` once when a session starts. (If the opener-restore in `ConfirmModal` wins the race, defer with `requestAnimationFrame` twice.) Check live.

#### UXA-14 (F3) should-fix: the Helm gate's tablist does not move focus, and its status announces every second

Evidence. `HelmUpgradeGate.tsx:132-136`: `onTabKey` toggles `tab` but never focuses the newly selected tab, so after ArrowRight the focused element is a `tabIndex={-1}` tab and a second arrow press is lost. `:117-121`: while loading, the status text changes to "Rendering the chart with your values… 4s", "…5s" every second, and `ConfirmModal`'s info status is `role="status"` (`ConfirmModal.tsx:348`), so it is announced each second. 03 section 9.5 intends an elapsed time for sighted users, not a stream of announcements.

Fix. (a) In `onTabKey`, compute the next id, `setTab(next)` and `document.getElementById(`helm-gate-tab-${next}`)?.focus()`; also handle Home and End. (b) Keep the status text constant ("Rendering the chart with your values…") and show the elapsed seconds in the description line as `<span aria-hidden>{elapsed}s</span>`.

### Nit

#### UXA-15 (F2) nit: small log-toolbar polish

- `LogViewBar.tsx:124`: the match arrows are buttons whose content is `↑` and `↓` with only `title`. Add `aria-label="Previous match"` and `aria-label="Next match"`.
- `LogViewBar.tsx:155`: the sentence "Filters match the line text, including any JSON. The Kubernetes timestamp isn't searched." is always visible, which costs a row in a narrow panel. Move it into the `title` of the Include field and keep it visible only inside the compact popover (02 section 3.3 shows it there).
- `LogViewBar.tsx:104`: the word-or-letter switch uses the window breakpoint (`sm:`), not the viewer's own `compact` state, so a 320 px panel in a wide window shows full words and wraps. Use the existing `compact` flag instead.
- Nothing wraps `Following` state on the follow button: add `aria-pressed={follow}` to the `follow` toggles (`LogViewer.tsx:159`, `MultiLogViewer.tsx:148`).

#### UXA-16 (F2) nit: copy drift from the strings v1.3.0 shipped

Evidence. `LogViewer.tsx:165` and `MultiLogViewer.tsx:155`: "Showing most recent 5,000 lines. {n} older lines dropped while following." The v1.3.0 override (brief v1.3.0 section 1.5 item 1) fixed "Showing the most recent 5,000 lines. {n} older lines were dropped while following." `LogViewer.tsx:166`: "Stream ended. Container stopped or connection dropped." differs from `podStreams.ts` `endedStripText` ("Stream ended. The container stopped or the connection dropped."). `LogViewer.tsx:168` lost the previous-instance hint "No previous instance found — container may not have restarted yet".

Fix. Restore the three v1.3.0 strings verbatim. Reuse `endedStripText` in the single viewer.

#### UXA-17 (F2) nit: jumping to a match near the bottom can re-enable follow

Evidence. `goToMatch` sets `follow` false then scrolls (`LogViewer.tsx:133-134`); the resulting scroll event runs `setFollow(scrollHeight - scrollTop - clientHeight < 40)` (`:170`), which flips follow back on when the match is within 40 px of the bottom, and the follow effect then scrolls away from the match.

Fix. Set a `jumpingRef` true in `goToMatch`, ignore the next scroll-driven follow update while it is set, and clear it after the `requestAnimationFrame` callback.

#### UXA-18 (F8, F9) nit: loading states in the read-only comparison dialogs are silent

Evidence. `ResourceCompareDialog.tsx:107-113` and `WorkloadActions.tsx` `RolloutDiffBody` render "Comparing…" inside an `aria-hidden` skeleton, and neither announces the result. `YamlSaveGate` and `HelmUpgradeGate` do (a status line plus an sr-only "Comparison ready").

Fix. Add `<div role="status" className="sr-only">{loading ? "Comparing…" : result ? `Comparison ready: ${changeCountText(result.changed)}.` : ""}</div>` to both.

#### UXA-19 (F10) nit: the Find results announce the whole list

Evidence. `FieldManagers.tsx:91`: `role="status"` wraps both the count line and the `ul`, so every keystroke re-announces all matches.

Fix. Put `role="status"` on the count `<p>` only; leave the `ul` plain.

#### UXA-20 (F3, F4) nit: three smaller gaps against the written states

- After a failed Save or Upgrade, the primary still reads "Save changes" or "Upgrade release" (`YamlSaveGate.tsx:91-94`, `HelmUpgradeGate.tsx:159`); 03 sections 8.4 and 9.5 show [Back to editor] [Try again]. Use `saveError ? "Try again" : ...` for the label.
- The dropped-by-schema row says "dropped by schema" twice, in parentheses and as the uppercase word (`DiffRows.tsx:120,130`). Drop the parenthetical.
- Custom-host write dialogs (`ResourceEditor`, `ResourceCreator`, `HelmInstallModal`, `MergeFromFileModal`) block the primary with native `disabled` plus `title={gate.reason}`, so keyboard users cannot reach the control to read why. Use `aria-disabled` plus a visible or sr-only reason, as `ConfirmModal` does.

#### UXA-21 (F7) nit: stale "Stopped waiting" card

Evidence. `ShellTab.tsx:160-164` keeps saying "{name} is still being added to this pod." after the container has reached `running`. Fix: when `card.kind === "running"`, show "{name} is running." with the same Attach button.
