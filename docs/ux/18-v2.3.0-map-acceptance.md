## Must-fix

### M1. Focus banner still says "connected" (MapPage.tsx:439)
Problem: "Showing what is connected to Pod x." is the old component meaning. The set is now the chain (upstream and downstream), so the sentence over-promises, and it gives no hint that siblings were left out. When the lineage equals the whole component (a Deployment in a one-app namespace keeps every ReplicaSet, Pod and config), the graph still looks unchanged, which is the user's original complaint ("same graph as before"), with no explanation. Heuristic: visibility of system status, match between system and real world.
Fix: replace the sentence with a count that shows what changed. `n` = `narrowed.nodes.length`, `m` = `map.nodes.length` (the backend component, not the namespace):
- n < m: `Showing the chain for {focusLabel}: {n} of {m} connected objects. Sibling objects and shared config are left out.`
- n = m and n > 1: `Showing the chain for {focusLabel}. Everything connected to it is part of the chain.`
- n = 1: `{focusLabel} has no connections. Showing it alone.`
"Show whole namespace" stays as the exit (it is accurate: focus off returns the namespace). Keep the banner `text-ink` on `bg-info/10`; no new tokens. Update `docs/ux/06-realtime-fleet.md` lines 240, 252, 362 and 375, which still carry "Showing what is connected to Deployment api-gateway" (MAP changed only L9, 2.3, 2.4).
Exact copy for line 252 wireframe: `ⓘ Showing the chain for Deployment api-gateway: 9 of 31 connected objects.   [Show whole namespace]`.

### M2. Labels stack on top of each other for long edges (GraphCanvas.tsx:364-379, graphLayout.ts:191)
Problem: a label sits at `anchors[0]`, the y of the next lane slot. Lane slots are `DUMMY_PITCH` = 16 px apart, and a label is up to 3 lines (about 40 px) tall, drawn upward from that y. A Service that selects three Pods draws three long edges (columns 3 and 4 are skipped), so three identical cards `selects · 7080 → 3000` land 16 px apart and overlap into an unreadable smear. Same for any node with 2+ long edges, such as a Pod with several Secrets across one gap. Heuristic: legibility (the user's complaint), WCAG 1.4.12-style overlap of text.
Fix, in the label layer only:
1. Group labels of the lit node by `anchor.x` and text. Draw one card per group at the median anchor y, with ` ×{n}` appended when n > 1: `selects · 7080 → 3000 ×3`.
2. Sort the remaining cards by y and enforce a minimum spacing of 44 px by moving a card down (keep the upward translate for the first). The card height cap is `line-clamp-3` at `leading-tight`, so 44 px is safe.
3. Add a test beside `GraphCanvas` or a pure helper `spreadLabels(items, minGap)` with a vitest (three anchors 16 px apart yield three y values at least 44 px apart; identical texts merge).

## Should-fix

### S1. Label text shrinks with zoom, Fit now zooms out more (GraphCanvas.tsx:274-276, 374; graphLayout.ts:17)
Problem: labels live inside the scaled layer, so 10 px text at z = 0.78 renders at about 7.8 px. A Pod lineage uses 7 columns: width = 2*24 + 6*304 + 184 = 2056 px; a 1600 px canvas fits at about 0.78, so node names (12 px) read about 9.4 px and kind lines (11 px) about 8.6 px. At 256 px pitch it was 0.9. The label is the one element the user must read on hover, and it is the smallest. Heuristic: legibility, WCAG 1.4.4 spirit (text must remain resizable and readable).
Fix: render the label layer outside the scaled div, in the `relative` wrapper (`width: lay.width * z`), at `left: a.x * z`, `top: a.y * z - 3`, so text stays 11 px at every zoom. Raise the label to `text-[11px]` and keep `maxWidth: (COL_PITCH - NODE_W - 8) * Math.max(z, 1)`. At z < 1 the gap shrinks on screen, so cap the width at `(COL_PITCH - NODE_W) * z - 8` but never below 96 px (allow it to cover a box edge at tiny zoom rather than clip). Do not change `COL_PITCH`; shrinking the pitch makes the elbows tight.

### S2. A label near the top of the canvas is clipped (GraphCanvas.tsx:373-374)
Problem: the card is drawn above `a.y - 3`. For a lane slot in the first island's top row, `a.y` is about 32 px (`PAD` 24 + 8), so a 3-line card (about 40 px) starts at y = -11 and is cut by the scroll container (there is no negative scroll).
Fix: when `a.y * z < 48`, draw the card below the anchor (`top: a.y + 3`, no `-translate-y-full`). One conditional, no new state.

### S3. Labels can sit beyond the viewport edge after arrow-key navigation (GraphCanvas.tsx:169-173)
Problem: `reveal` uses `scrollIntoView({block:"nearest", inline:"nearest"})`, so the focused node can end flush with the right edge, and its outgoing labels (in the gap to its right) are off screen. Moving by keyboard is exactly the case where labels appear on focus.
Fix: give each node button `style={{ scrollMarginInline: (COL_PITCH - NODE_W) * z / 2 + 8 }}` and `scrollMarginBlock: 24`. Verify under "Needs visual check" (scroll-margin and CSS transforms interact differently across WebView2 and WKWebView; if it does not move the scroll, fall back to scrolling by a computed `scrollLeft` delta).

### S4. Labels have no Esc dismissal (GraphCanvas.tsx:105-107, 209-225; WCAG 1.4.13 Content on Hover or Focus)
Problem: the cards appear on hover or focus and cannot be dismissed without moving focus or the pointer; they are also `pointer-events-none`, so the pointer cannot rest on them. The content is duplicated in the strip, but 1.4.13 has no exception for that.
Fix: in `onNodeKey`, on `Escape` while at least one label is drawn, set a `dismissedFor` state to the lit id, hide the layer, `preventDefault()` and `stopPropagation()`. Clear it when `lit` changes. When no label is drawn, do nothing so Esc still reaches the layer below (panel, palette). "Hoverable" is met in spirit because the card only informs; note it in the code comment.

### S5. The kind chips say "in this namespace" while focused (MapPage.tsx:73, 78)
Problem: with a lineage the chip counts come from the narrowed set, but a zero chip says "No objects of this kind in this namespace." That is false when the namespace has Storage objects that are outside the chain (the screenshot shows `Storage 0`).
Fix: when `focus` is set, the title and the sr-only text read `No objects of this kind in this chain.` Pass a `scopeWord` prop ("namespace" or "chain") to `KindFilter`. The chip counts themselves match the graph and List (both read `narrowed`): correct.

### S6. Announcement and too-many copy still use the old meaning (MapPage.tsx:206, 265-269)
Problem: after "Show only this" the live region says "Map loaded. 9 objects, 8 connections." with no sign that the set changed. The too-many hint says "{focus} connects to {n} objects", and `n` is now the chain size after hide and group.
Fix:
- Announcement when focused: `Showing the chain for {focusLabel}. {n} objects, {e} connections.` (key stays `scope/focusStr/state`, so it fires once per focus change).
- Too-many with focus: `The chain for {focusLabel} has {prepared.count} objects (the limit is 400). Hide ConfigMaps and Secrets, or start from a narrower object.`
- Backend `truncated` with a focus (the Rust ceiling counts the whole component, noted in `lineage`): `The objects connected to {focusLabel} are too many to load (more than 2,000). Start from a narrower object.` Today it says "More than 2,000 objects in namespace {ns}", which is wrong for a focused request.

### S7. After "Show only this" the view keeps the old zoom and scroll (GraphCanvas.tsx:128-152, 176-182)
Problem: the canvas anchors the focused node at the same screen offset, so the narrowed graph appears wherever the old one was, possibly zoomed out to 50% or scrolled away. The user pressed a button to see one chain; they should see the whole chain.
Fix: when `epoch` changes because of a focus change, call `fit()` once after the new layout. Make `fit()` clamp at 1 (`Math.min(1, ...)`) for this automatic call; the visible Fit button may keep zooming up to 2, but at 200% a one-object lineage fills the canvas with a single giant box (see N3). Keep the details strip selection on the focused node.

### S8. Vertical runs of different sources in one gap share an x (graphLayout.ts:164-167)
Problem: the code already marks it `ponytail:`. In the lineage graphs it is common: `Service -> Pod` (through lanes) and `HPA -> Deployment` both run vertically in the gap between columns 2 and 3 at the same x, so lines merge and the reader cannot tell which line ends where. The dash family helps only when the families differ. Heuristic: recognition of direction (arrowheads alone do not separate merged lines).
Fix (small): per gap, give each distinct source id its own x offset, `gapX + (i - (n - 1)/2) * 6`, clamped to +-48 px (gap is 120 px). Edges from the same source keep one x, so a fan-out (Deployment to five ReplicaSets) stays one clean bus as in the screenshot. Long edges keep their source's offset through every gap they cross. Needs a `graphLayout.test.ts` case: two sources in one gap get different x, two edges of one source share it, every point stays inside the canvas.

### X1. A card can cover the edge of a neighbouring box (should-fix; GraphCanvas.tsx cards, graphLayout.ts tracks)
Problem: since S8 the anchor x is the edge's own track, spread evenly across the 120 px gap, no longer the gap centre. With two or more owners in a gap a track sits 20 to 60 px from a box edge, and a 96 to 112 px card centred on it extends over the box beside the gap, hiding up to 36 px of its edge, where the status word ("✓ OK") is. The 2.3 rule "never covers a box" is broken again.
Fix: clamp the card centre to the gap in screen space. `gapLeft = (PAD + col * COL_PITCH + NODE_W) * z` where `col = Math.floor((a.x - PAD) / COL_PITCH)` (export `PAD`, or add the gap bounds to `PlacedEdge.anchors`); `gapRight = gapLeft + (COL_PITCH - NODE_W) * z`; centre = `clamp(c.x, gapLeft + w/2 + 2, gapRight - w/2 - 2)` with `w` = `labelW`. When `w` is larger than the gap (z below about 0.8), centre on the gap. Merge keys keep the unclamped x. Add a vitest on a pure `clampToGap(x, col, z, w)`.

### X2. The scroll margin is half a gap, not a full gap (should-fix; GraphCanvas.tsx node `style`). Error in S3 of this document.
Problem: `scrollMarginInline = gap*z/2 + 8` (68 px at 100%) reveals only half of a 120 px gap, so a card can still be half off screen after an arrow-key move. My S3 fix said "half-gap + 8"; that was wrong, a card needs the full gap.
Fix: `scrollMarginInline: (COL_PITCH - NODE_W) * z + 8`; `scrollMarginBlock: 24` stays. A node plus both gaps is 184 + 2 * 128 = 440 px; on a narrower canvas the browser clamps the margin, which is acceptable.

### X3. The "too many" block title still says "namespace" while focused (should-fix; MapPage.tsx:271)
Problem: the title "This namespace has too many objects to draw." sits above the new body "The chain for X has 412 objects ...". Two scopes in one block.
Fix: title `This chain has too many objects to draw.` when `focus` is set and the state is not truncated; `Too many objects to load.` when `focus` is set and the state is truncated; unchanged without a focus. Update the matching row in UX 06 (3.5 table) if it quotes the title.

### N11. Flipped first card and the 44 px spread (note)
A card flipped below its anchor (screen y under 48) occupies about y+3 to y+43. The next card, pushed to y+44, is drawn above its own anchor and covers about y+1 to y+41, so the two overlap. It needs two or more labelled edges on one gap in the top 48 px of the canvas; the `ponytail:` comment in the code names a similar ceiling. Fix only if seen: when the first card is flipped, start the spread at `y + 88`.
