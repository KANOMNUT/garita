# UX 26: v2.4.1 acceptance, from browser captures

Post-implementation UX acceptance of the run `claude/group-crds-v2.4.1-d05adq` (the grouped CRDs page and the custom resource panel), at code commits `2acff7b` (F1), `44ea712` (F2) and `8700010` (F3) on top of the Rust in `6734829` and `208b0ae`. Spec: sections 2.7 and 2.8 of `docs/impl/v2.4.1-tasks.md`, as ruled by the user decisions Q1 to Q11 in the plan, plus the "For U1" list in `.claude/checkpoints/claude-group-crds-v2.4.1-d05adq/W3R-tech-lead.md` (the tab-switch record, RBAC hints under "All namespaces", the delete confirm, the Events footer, the copy labels and the four review states). The fix batch FX-U1 (commit `5bd404d`) was recaptured and judged in section 7; sections 1 to 6 keep the findings as first written, at `8700010`.

## 0. What this document is based on, and what it is not

**Evidence.** I drove the app in Chromium (Playwright 1.63) against a Vite dev server of the working tree (127.0.0.1:1525, started and stopped by me; port 1420 was free and untouched) with a mocked `window.__TAURI_INTERNALS__` and invented sample data: 26 CRDs in 11 API groups (cert-manager, ArgoCD, Cilium, Gateway API, Flux, Prometheus operator, Cluster API, and a made-up `acme.io`), namespaced and cluster-scoped objects, a CRD that is not established, a CRD with no served version, conditions with `Ready`, `Reconciling` and `Stalled`, and a mock whose preview, apply, delete and `can_i` answers I could flip per scenario. I took 160 PNG files (almost every state in both themes) and read DOM probes (`aria-*`, tab order, computed contrast, bounding boxes, `scrollLeft`) for what a still image cannot show. Everything is in the scratchpad `/tmp/claude-0/-home-user-garita/e4b43a10-203a-5e87-8cff-7fbd2c44c3cb/scratchpad/u1/`: `mock.js` (the backend), `lib.js` (driver helpers), `b1.js` to `b9.js` (scenarios), their `*.json` results, and `shots/` (PNG). I opened 30 of the shots myself, in both themes; the other shots named in the Evidence column rest on the DOM probe named next to them. I made no source edit. The one "fix check" below (X1) is a listener injected into the page, not a change to the repository.

The V1 harness that UX 25 used was no longer on disk, so this mock is new and smaller; it covers only the commands the two features call.

**Limits, stated once.**

- Chromium on Linux with a mocked backend. Not WebKit (macOS), not WebView2 (Windows), not WebKitGTK, and not a real cluster. Every cluster answer (the 403 text, the dry run, the conflict, `SelfSubjectAccessReview`, finalizers, the 15 s poll finding an object gone) was invented by `mock.js`. A pass means "the UI draws and behaves as specified on this data", not "works against a cluster".
- No Tauri window chrome, no native tooltip (`title` is checked in the DOM, not seen), no real clipboard permission model (I granted it to get "Copied" and replaced `writeText` with a rejection to get "Couldn't copy").
- The fonts are the shipped ones: `document.fonts.check` is true for Inter and JetBrains Mono, so widths measured here are the real widths for this data.
- The minimum window is 1024 x 640 (`tauri.conf.json`). I used 1024 x 640, 1280 x 800, 1440 x 900 and 1500 x 800/900, and a 320 px panel.
- The names in the sample data are real CRD names (`ciliumclusterwidenetworkpolicies.cilium.io`, `kubeadmcontrolplanetemplates.controlplane.cluster.x-k8s.io`), because the table width depends on them.

**Result words.** *pass*: the shots and probes show what the spec says. *partial*: part passes, part has a finding. *fail*: the spec is broken at a size or state a user will meet. *owed*: only a real build or cluster can show it (section 5).

## 1. Verdict

**2026-10-30, after FX-U1 (`5bd404d`, re-checked in section 7): ship.** X1, X2, X3, X5, X6 and X8 all pass on the real code in both themes at 1024, 1280 and 1500 px with the long-name data. Two new Polish observations (X14, X15) are older table behaviour and do not block. What stays owed on a real build is section 5.

**Original verdict (at `8700010`, before FX-U1): fix first, with one small batch (FX-U1, section 4), then W3R again.** No Critical finding. All write flows pass in both themes: Edit, the review gate in all four states, the namespaced and the cluster-scoped delete confirm, read-only and RBAC-denied states. The two Significant findings are both on the new CRDs page and both in F1's two files:

- **X1.** A keyboard user who tabs to a group header makes the table scroll sideways and every group label leaves the screen (label 306 px off at 1280, 562 px off at 1024). The header button is as wide as the whole table, and the table is wider than its pane. A mouse click does not do it.
- **X2.** The **Instances** button, the new way into a CRD's objects, is the eighth and last column. With CRD names like Cilium's or Cluster API's the table is 1188 to 1303 px wide, so the button's right edge is at 1430 to 1545 px: off screen at 1280 px, at 1024 px, and even at 1440 px (visible area 1128 px). The panel's **Show instances** link still works, so the task is not blocked; that is why this is Significant and not Critical.

One more cheap fix in the same file belongs in the same batch (X3, a loud rule under every group header). Everything else is Polish and goes to "later" (section 3).
