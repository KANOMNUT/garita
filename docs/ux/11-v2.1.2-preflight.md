# UX 11: v2.1.2 preflight, kubeconfig `proxy-url` provenance (#50)

Bounded delta preflight for `docs/impl/v2.1.2-tasks.md` (DRAFT) §4 F1. Source copy: `docs/ux/05-theme-settings-platform.md` §11. Checked against `src/components/ContextSwitcher.tsx`, `src/App.tsx` (`ClusterAccessBanner`), `src/types/k8s.ts`, `src-tauri/src/commands/cluster_info.rs`. Hard constraint kept: no proxy form, no settings screen, provenance only.

## 1. Findings

**Critical**

- **C1. Credentials can leak through `ClusterAccess.message`.** The brief scrubs userinfo in `app_log` and strips it in `display_proxy`. But `check_cluster_access` returns `message: msg` (`e.to_string()`, cluster_info.rs, the generic `Err(e)` arm) straight to the banner `<p>`. A connect error from the proxy path can echo the proxy URL, userinfo included. Principle: error prevention, and the "never show credentials" rule of UX-05. Fix: when `via_proxy`, the backend applies the same userinfo scrub (`scheme://<redacted>@`) to `message` before returning it, with a test. The frontend must not be the only line of defence.
- **C2. Banner has no source for `{host}`.** `ClusterAccess` only gains `via_proxy: bool` (T51-3); the banner (`App.tsx`) receives only `access`. Fix: the banner takes the host from the active context's `KubeContext.proxy` (`useKubeContexts` is already used in `App.tsx`; find by `currentContext`). Do not put the host into `message` from the backend, or the UI cannot style or truncate it.

**Significant**

- **S1. "Unreachable" also covers TLS, cert and timeout failures** (the classifier matches `tls`, `certificate`, `timed out`). UX-05's sentence "The proxy refused the connection or is unreachable" would then be wrong for a cert error. Fix: use neutral wording and always show the raw detail line (see §3).
- **S2. Brief and UX-05 copy differ** ("Couldn't reach the cluster through proxy {host}." vs "Can't reach <ctx> through proxy …"). Pick one (Q1).
- **S3. Brief drops two UX-05 variants** (407, unsupported scheme). See Q2 and Q3.
- **S4. Existing row uses `text-dim` for text** (`ContextSwitcher.tsx` cluster, source and provider lines), which fails WCAG 1.4.3 and `ui.md`. The new line must use `text-mute`; do not copy the neighbouring `text-dim` class. Fixing the old lines is out of scope for this release (Polish, noted only).

**Polish**

- **P1.** `ClusterAccessBanner` has no live-region role. An unreachable result that appears after a context switch is silent to screen readers. Add `role="alert"` to the strip for `unreachable` and `unknown` only (`bad` tiers). Optional, not blocking.

## 2. ContextSwitcher row

Current row, top to bottom: name line, `cluster` (mono), `context defined in …` line. Insert the proxy line **between** `cluster` and `context defined in`, so the connection facts stay together and file provenance stays last.

```
 o  prod-eu            [read-only]
    prod-eu.example.com:6443
    via proxy proxy.corp:3128
    context defined in config
```

| Case | Text | Notes |
|---|---|---|
| `proxy` null | render nothing | No "no proxy" text, no empty line, no reserved height. |
| `http://` or `https://` | `via proxy ` + `host:port` | |
| `socks5://` | `via SOCKS5 proxy ` + `host:port` | |
| `socks5h://` | `via SOCKS5 proxy ` + `host:port` | Same label; the exact scheme appears only in the `title`. |
| IPv6 | `via proxy [::1]:3128` | Keep the brackets exactly as stored; never re-parse or strip them. |
| Port missing in `proxy` | show host only | Do not invent a default port. |

Styling: `text-[10.5px] text-mute`, label in sans, `host:port` in `mono`. 10.5 px matches the cluster line above it; this deviates from UX-05's 11 px on purpose (an 11 px line under a 10.5 px line looks like a hierarchy inversion). Role tokens only, no colour literals.

Layout and truncation: `flex min-w-0 gap-1`. Label `shrink-0`. Host part `truncate min-w-0`. The `:port` suffix `shrink-0` so a long host loses its middle, not the port that people need to check. Split on the last `:` after the closing `]` for IPv6. Whole line is inside the existing row `<button>`, so no extra tab stop.

Tooltip: `title="Requests to this cluster go through {scheme}://{host:port} (proxy-url in the kubeconfig cluster entry)"`. Built from the same stripped `proxy` value, so it never holds userinfo. The title is a convenience: all essential info is already visible text.

Defence in depth (frontend): one pure helper `proxyLabel(proxy: string | null)` returns `{ label, host, port, title } | null`. If the value contains `@` it returns `null`. A `*.test.ts` beside it covers: null, http, https, socks5, socks5h, `[::1]:3128`, long host, no port, a value containing `user:pw@` (must return null).

## 3. Trust banner copy by state

Banner stays the existing strip (`bg-bad/10 ring-bad/30 text-bad` for unreachable and unknown; `warn` for auth and forbidden). No new states, no new colours.

| State | `via_proxy` | Copy |
|---|---|---|
| `unreachable` | false | Existing text, unchanged. |
| `unreachable` | true | Line 1 (semibold): `Couldn't reach {ctx} through proxy {host:port}.` Line 2: `Check the proxy-url in your kubeconfig and your network.` Line 3 (mono, existing `message`, already scrubbed per C1): the raw error. |
| `auth` | either | Unchanged. A 401 comes from the API server, so the proxy worked; mentioning it misleads. |
| `forbidden` | either | Unchanged, same reason. |
| `unknown` | either | Unchanged. We cannot tell proxy from server; the raw message stays. |
| `ok` | true | No banner. |

Notes:

- `{host:port}` renders in `mono` with the same IPv6 rule as the row. If `via_proxy` is true but the active context's `proxy` is null (stale cache), drop the host: `Couldn't reach {ctx} through the proxy.`
- Line 2 deliberately avoids "refused" (S1). The detail line carries the specifics.
- Wrap: the strip already uses `whitespace-pre-wrap`; long hosts must `break-all` on the host span only.
- Not a button, no new action. Dismiss behaviour unchanged.

## 4. Accessibility summary

- Row: the proxy text is inside the row button, so the accessible name reads name, cluster, "via proxy proxy.corp:3128", source. No `aria-label` override (it would hide the new text). No icon, so nothing to hide.
- Contrast: `text-mute` on the switcher surface, same as other secondary text; `dim` is never used for the new line.
- Banner: text-based, icon already `aria-hidden`-able; add P1 role if accepted. Colour is never the only signal (the words "through proxy" carry the meaning).
- No hover-only information: the tooltip repeats visible content.

## 5. Open questions (recommended default first)

1. **Which banner sentence, brief or UX-05?** Default: `Couldn't reach {ctx} through proxy {host:port}.` (names the context, matches the existing "Can't reach {ctx}" pattern in `ResourceCompareDialog`).
2. **407 variant ("The proxy … rejected the request (407)")?** Default: defer. The backend classifier cannot distinguish 407 today; it falls into `unreachable` with the raw error visible on line 3. Promoting it needs a new backend class, which is scope for the tech-lead.
3. **Unsupported-scheme warn row ("Proxy type not supported")?** Default: drop for v2.1.2. The brief makes `display_proxy` return `None` for garbage, so the row is simply silent and the context still loads. Revisit if support reports show confusion.
4. **Scrub `ClusterAccess.message` when `via_proxy` (C1)?** Default: yes, backend, with a test. This is a security/scope decision for the tech-lead, not a copy choice.
5. **Show `https://` proxy differently from `http://`?** Default: no; the scheme is only in the `title`.
6. **Apply `role="alert"` to the banner (P1)?** Default: yes for `unreachable` and `unknown`, as a one-line change; skip if the release is tight.
