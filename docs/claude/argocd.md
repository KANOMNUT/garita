# ArgoCD

Section names are grep targets (`CLAUDE.md`, Detailed docs).

## ArgoCD

Applications are namespaced `argoproj.io/Application` CRDs read via `DynamicObject`, listed cluster-wide. The API version is discovered at runtime (see ArgoCD Lens Parity). `tabsFor()` returns four tabs:

- **Overview**: the Actions card (sync options, Sync / Refresh / Hard refresh) first, then the Last operation badge, commit box and fields (including Sync policy). Health and Sync are chips in the panel header, not in the Overview.
- **Resources**: `status.resources[]` with Sync and Health; 21 standard kinds are clickable (the kind is a native button, so Enter opens it); Health and Sync filter groups; a `Group by kind` toggle; own Refresh / Hard refresh. The tab shows the resource count, and a red count named "Degraded or missing" while some resource is Degraded or Missing.
- **History**: `status.history[]`, each with "Roll back to this revision…" → `rollback_argocd_app(context, namespace, name, historyId)`, keyed by `ArgoCdHistoryEntry.id` (React key too). The backend reads revision and source(s) from the live object; the display string is never sent. Disabled with a reason when `ArgoCdApp.auto_sync`. The entry that is running now carries a neutral **Current** chip (see Sync options, Force confirm and History below). `short_revision` shortens **only** a 40-hex SHA to 7 chars; other values (chart versions, `HEAD`, tags) pass through (the Applications list's `last_commit` uses it too, see Columns below); multi-source shows `revisions[]` joined with `, `.
- **Events**: K8s events for the app.

**Click-to-navigate:** `ArgoCdResourcesTab` maps kinds via `KIND_TO_RESOURCE_TYPE` and calls `onNavigate(kind, namespace, name)`. `App.tsx` sets `navigateSearchRef.current = name` before `setActiveResource` / `setNamespace`, so the target page opens with the name in the search box.

**Commit metadata** is fetched lazily with three fallbacks: port-forward plain HTTP → K8s API proxy anonymous → K8s proxy with JWT from `argocd-initial-admin-secret`.

### Resource Health — K8s-native computation

ArgoCD v2.8+ (`resourceHealthSource: appTree`) keeps per-resource health only in controller memory (REST API, auth required). So `get_argocd_app_resources` computes health **from K8s `.status`** via `k8s_resource_health()`, per `(group, kind)`. **Never call the ArgoCD REST API for health.**

| Kind | Healthy when | Other states |
|---|---|---|
| `apps/Deployment` | `Available=True` + `availableReplicas >= spec.replicas` | replicas 0 Suspended; `Progressing=True` Progressing; else Degraded |
| `apps/StatefulSet` | `readyReplicas >= spec.replicas` | else Progressing |
| `apps/DaemonSet` | `numberReady >= desiredNumberScheduled`, no misscheduled | misscheduled > 0 Degraded |
| `apps/ReplicaSet` | `readyReplicas >= spec.replicas` | else Progressing |
| `core/Pod` | `Running` + `Ready=True`, or `Succeeded` | `Failed` Degraded; `Pending` Progressing |
| `core/PersistentVolumeClaim` | `Bound` | `Lost` Degraded; `Pending` Progressing |
| `core/Service` | LoadBalancer with ingress; ClusterIP/NodePort/ExternalName always | LB without IP Progressing |
| `autoscaling/HorizontalPodAutoscaler` | `AbleToScale=True` + `ScalingActive=True` | `AbleToScale=False` Degraded |
| `networking.k8s.io/Ingress` | has `status.loadBalancer.ingress` | else Progressing |
| `batch/Job` | `Complete=True` | `Failed=True` Degraded; else Progressing |
| everything else | always Healthy (no fetch) | Sync shows drift |

Fetch failure (resource deleted since reconcile): `Missing`. `kind_to_plural()` handles irregular plurals for `ApiResource`.

**Sync and Health are independent; never collapse or fall back one to the other.** Sync (`status.resources[].status`) = does the cluster match git. Health (K8s `.status`) = does it work. A hand-edited ConfigMap goes `OutOfSync` after the next reconcile (~3 min) and stays `Healthy`.

### Panel header, Resources filters and actions (UX review B1)

- **The header shows Health and Sync as two chips** (`ArgoStatusChip` in `ResourceDetailPanel.tsx`, from `argoHealthPill(health_status)` and `argoSyncPill(sync_status)` in `src/utils/argoStatus.ts`; the glyph is `aria-hidden` and an `sr-only` "Health: " / "Sync: " prefix names each). The one-word chip (`statusChip`, Healthy / Not healthy) is for every other kind. `isHealthy("argocd")` reads `health_status === "Healthy"` alone (`isArgoHealthy`), so a Healthy but OutOfSync Application, a Progressing, Suspended or Missing one is no longer called Degraded. The three pill tables (health, sync, operation phase) and the Resources filter logic are pure functions in `src/utils/argoStatus.ts` (with `argoStatus.test.ts`), shared by the header, the Overview and the Resources tab; Suspended and Unknown are neutral (`mute`). Do not copy a pill map into a component, and do not derive one of Health and Sync from the other: the tests pin that independence. The Applications list's Health and Sync cells (`ArgoPillCell` in `ResourceViews.tsx`) read the same `argoHealthPill` / `argoSyncPill` (`${PILL} ring-1 ${pill.cls}`) and draw the glyph with `ArgoGlyph` (`src/components/ArgoGlyph.tsx`, the Pause icon for Suspended), so Missing is amber and Degraded has the cross in the list, the Resources tab cards and the header alike; the list's old local maps are gone (`healthPillClass` / `healthIcon` in `ResourceViews.tsx` remain for the Certificate Ready column only).
- **Overview.** The operation pill is labelled `Last operation: <phase>` so it is not read as a third status. A `Sync policy` row reads `Automated` when `ArgoCdApp.auto_sync` and `Manual` otherwise (the field already gates rollback in History).
- **Resources filters** are two independent single-select groups, `role="group"` Health and Sync, each chip `aria-pressed` and labelled with the status word and its count (`Degraded 2`). Counts are per status and always from the full list: a Missing resource counts under Missing, not Degraded. **"Healthy" is `health_status === "Healthy"` alone**, so a Healthy but OutOfSync resource counts under both Healthy and OutOfSync. Healthy, Progressing, Degraded, Missing, Synced and OutOfSync always show; Suspended and Unknown show only while some resource has that status (or the filter is on). The two groups combine with AND (`filterArgoResources`); the row order is `argoSortScore`; `isDegradedOrMissing` feeds the row accent and the tab badge. The row order (Degraded and Missing, then OutOfSync, then Progressing) and the tab-strip badge (Degraded or Missing) are unchanged.
- **Actions.** Sync, Refresh and Hard refresh carry `aria-disabled` while busy or blocked by read-only mode, look disabled, and the read-only reason is printed under the buttons (the Resources tab Refresh and Hard refresh buttons do the same). A busy request does not drop focus: the handlers bail out instead of using `disabled`.
- **Action feedback** is `{ tone: "ok" | "error", text }`, never derived from the text. A success clears after 4 s; an error stays until the next action starts, so it can be read and copied. Errors read `Couldn't sync <name>: <message>` and `Couldn't refresh <name>: <message>`, in a `role="alert"` paragraph; success is `role="status"`. The Dry-run hint still keys on the backend's `Dry-run` prefix (a string match on backend wording, noted, not changed).

The Resources tab Refresh / Hard refresh call `useRefreshArgoCdApp`, which invalidates `["argocd-apps", context]` and `["argocd-app-resources", context, ns, name]`.

### Sync options, Force confirm, History and Resources tab (UX review B2)

- **Sync options** (`ArgoCdActionBar`) are three native checkboxes in a `fieldset` (an sr-only `Sync options` legend), each with its help line always visible, so the user reads what Prune and Force do before choosing them: Prune "Removes resources that are no longer in git.", Dry run "Simulates the sync. Nothing is changed.", Force "Overwrites resources that conflict with git." The Force sentence is the older wording kept on purpose (user decision Q10 A): it is **not** verified against upstream gitops-engine, so `open-items.md` carries a live check. The options still feed `syncOpts` and the `.operation` patch unchanged (see the write contract below); only the controls and the copy changed.
- **Sync with Prune or Force always goes through a confirm** (user decision Q9 A), even while the cluster's typed-confirm guardrail is off. The dialog is the one `ConfirmModal` of `ArgoCdActionBar`; its title, copy and button follow the options: Prune alone "Prune resources on sync" / "Sync with prune" (with the count of resources that `requires_pruning`, as before), Force alone "Force sync <app>" / "Sync with force", both "Prune resources and force sync" / "Sync with prune and force". A dry run says nothing will be deleted or overwritten and is not styled destructive. Plain Sync and Dry run alone keep the `useGuardedAction` confirm (typed-confirm guardrail on only). Bulk Sync from the Applications list is unchanged: `prune: false, dryRun: false, force: false`, and it never offers Force.
- **The Resources tab has no "diff" expander** (user decision Q7 A). The old button on OutOfSync rows opened a fixed sentence that sent the user to a YAML tab an Application panel does not have. The OutOfSync pill and the clickable kind (it opens the object) carry the meaning; do not add a "diff" or "details" control that shows no diff.
- **Resources tab feedback** matches the Overview actions: success "Refresh requested. ArgoCD updates the status when it finishes." in a `role="status"` line that clears after 4 s; an error `Couldn't refresh <app>: <message>` in a `role="alert"` line that stays until the next refresh starts. The buttons read `Refresh` and `Hard refresh`; their titles say what they do ("Asks ArgoCD to re-check drift now; without it the check can lag by about 3 minutes." and "Asks ArgoCD to clear its cache and re-fetch from git."). The grouped view's per-kind header reads "N Degraded or Missing", because `isDegradedOrMissing` counts both.
- **History.** `ArgoCdHistoryEntry.message` is the **whole commit message** (every line, CRLF turned into LF, trailing whitespace and blank lines trimmed; `history_entry_message` in `argocd.rs`; the Applications list's last-commit message stays the first line). The row shows revision, date and the **first line** of the message (`message.split(/\r?\n/, 1)[0]`, cut with an ellipsis); the expanded entry shows **all lines first** (`whitespace-pre-wrap`, so line breaks are kept, and `wrap-break-word`, so a long line wraps; `No commit message recorded.` when empty), then the author, the ISO time and the rollback button. The Change timeline (`mergeTimeline` in `timeline.ts`) uses only the first line of the message (`first line. by author`); the History tab alone shows the whole message. The chevron is always visible (it used to appear on hover). **Current** marks the entry returned by `liveHistoryId(history, last_commit)` (`src/utils/argoHistory.ts`, user decision Q11 A): the highest `id` whose `revision` equals `ArgoCdApp.last_commit` by exact string match, and none when nothing matches or `last_commit` is `—`. This is sound only because `last_commit` and each history `revision` both go through `short_revision` (a 40-hex SHA becomes 7 characters, anything else stays whole), so a chart version `10.11.12` never matches `10.11.1`. A multi-source Application is not special-cased: its history revision is `revisions[]` joined with `, `, so it matches only if `last_commit` is that exact string, which it is not in practice (no chip). The marker does not disable or hide the rollback button.
- **Long values.** `KV` has a `title` and a `wrap` mode; the Overview's Repo, Path, Target revision and Dest cluster wrap, and the commit pill wraps, because `last_commit` can be a whole chart version, tag or branch. The Applications list Revision cell cuts both lines with an ellipsis and a `title`.
- **Not shown (Q8, deferred):** why the last operation failed. The Overview shows only `Last operation: Failed`; the reason is in `status.operationState.message`, which `ArgoCdApp` does not carry yet. It needs a Rust field in a later run.

## ArgoCD Lens Parity (v1.0.0)

- Commands `list_argocd_appsets`, `list_argocd_projects`, `list_argocd_repositories`: `context` only, cluster-wide via `Api::all_with`.
- **Runtime version discovery:** `argo_api_resource(client, kind, plural)` uses `kube::discovery::group(client, "argoproj.io")` + `recommended_kind`. Only `DiscoveryError::MissingApiGroup` means "not installed" → `Ok(None)` (lists return empty; the four mutations return a clear `Err`). Every other error propagates. **Never hardcode a version matrix.** (Flux, Gateway, cert-manager and the `pods.rs` arms still hardcode one version each.)
- `ResourceType` gains `argo-appsets`, `argo-projects`, `argo-repos`. Only the first two are in `SelectedResource`; repos have no detail panel, no `tabsFor()` branch, no `get_resource_yaml` arm.
- **Repositories:** Secrets labelled `argocd.argoproj.io/secret-type in (repository, repo-creds)` in the ArgoCD namespace, falling back to `argocd-cm` `repositories`. **Return an allowlist of non-secret fields only.** `auth_method` is derived from which keys exist: `sshPrivateKey` "ssh", `password` "https", `githubAppPrivateKey` "github-app", else "none".
- **7-bucket health strip** in `ArgoCDView` (Total / Synced / Healthy / OutOfSync / Degraded / Missing / Progressing) as filter cards. "Healthy" = `health_status === "Healthy"` alone.
- Columns: **Destination** (`dest_namespace`, `dest_server` tooltip); **Revision** shows `last_commit`, `target_revision` secondary. `last_commit` is `last_commit_display(status.sync.revision)` in `argocd.rs`: `—` when the revision is empty, else `short_revision`, so a 40-hex SHA is shortened to 7 characters and a chart version (`10.11.12`), tag or branch name stays whole. The Overview shows the same value. It is the same string as `ArgoCdHistoryEntry.revision` for the same revision (both go through `short_revision`), so a client can match the two exactly. **Never slice a revision by byte index:** `panic = "abort"` kills the app on a non-ASCII revision (the old `revision[..7]` did), and it cut `10.11.12` to `10.11.1`. `last_commit_display_rules` pins this.
- **Bulk sync/refresh:** multi-select with shift-range, `Promise.allSettled`. **Bulk sync always sends `prune: false, dryRun: false, force: false`**; prune is single-app only.
- **Bulk selection covers only the rows the table shows** (v2.3.1). `ArgoCDView` derives one `shown = shownRows(filtered, search, argoKey, argoColumns, sort)` (`utils/tableRows.ts`: the health filter, then the table's own search predicate, then its sort, in the displayed order) and uses it for both Select all buttons, the shift-range (`rangeSelect`), `selectedApps` and the "N selected" count. The table runs the same `searchRows` / `sortRows`, and `GenericResourceTable` takes optional controlled `sort` / `onSortChange` props so `ArgoCDView` knows the displayed order. The selection still clears when the health filter or the TopBar search changes, not on a sort. Do not build a selection set from `filtered` or `data`.
- **"Managed by"** in the Summary tab, precedence: `annotations["argocd.argoproj.io/tracking-id"]` (segment before first `:`) → `labels["argocd.argoproj.io/instance"]` → `labels["app.kubernetes.io/instance"]` (shown as "possibly managed by"; Helm sets it too). ArgoCD's default tracking is `label`, so `get_resource_metadata` returns `{ annotations, labels }`.
- **Prune risk before confirm:** `ArgoCdResource.requires_pruning`; `ArgoCdActionBar` shows `⚠ prune will delete N resources` and lists them.
- Cut, do not re-add: Settings > Clusters view, "Open Argo CD UI" button, AI assist, a separate GitOps dashboard page, per-kind summary cards. Recent-activity timeline deferred (events expire in ~1 h).

### ArgoCD CRD write contract (immutable)

No REST API, no client library, so these shapes are hand-written and fail silently:

- **Sync = `.operation`**, JSON merge patch.
- **Force = `operation.sync.syncStrategy.hook.force`.** `SyncOperation` has no `force` field (`operation.sync.force` is a silent no-op). Use `hook`, not `apply`: `IsApplyStrategy()` makes gitops-engine skip sync hooks.
- **Omit `revision`** unless the caller passes one, so `targetRevision` applies. Hardcoding `"HEAD"` synced tag-pinned apps to HEAD. Omission also handles multi-source apps (`revisions[]`).
- **Guard:** reject when `.operation` is already non-null. Check `.operation` presence, **not** `operationState.phase` (right after a patch, phase still shows the previous `Succeeded`). Without it, the controller resumes the in-flight op and discards the new options.
- **Refresh = annotation** `argocd.argoproj.io/refresh` = `normal` | `hard`; the controller removes it.
- `dryRun: true` still reports through `status.operationState`.
- **Rollback is the only sanctioned `syncStrategy.apply`** (upstream `Rollback` parity). `rollback_argocd_app` restores the entry's full revision **and** `source` (or `sources` + `revisions`), sets `syncStrategy: { apply: {} }`, `prune: false`, `dryRun: false`, copies `spec.syncPolicy.syncOptions` only when non-empty. **Never align sync and rollback.** No `force` key in a rollback patch. Pure `build_rollback_patch` guards in order: operation in progress → auto-sync enabled → no entry with that `id` → entry has no source (Argo CD ≤ v1.4). Auto-sync enabled = `spec.syncPolicy.automated` is an object whose `enabled` is not `false` (`auto_sync_enabled`, also fills `ArgoCdApp.auto_sync`).
- Verify changes to `sync_argocd_app` / `refresh_argocd_app` against upstream source, never memory. Live-cluster confirmation is still owed.
