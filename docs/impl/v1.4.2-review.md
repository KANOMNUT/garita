## Runtime reasoning (the tests run in node, so I traced the browser paths by hand)

- **`appearance.ts` snapshot.** `getSnapshot` returns the module-level `state`, which only `commit` replaces, and only when a field changed (`:64`). The identity is stable, so `useSyncExternalStore` does not loop.
- **`matchMedia` listener.** It is registered once, in `initAppearance` at module top level in `main.tsx`, outside React, so StrictMode does not double it. With an explicit Light or Dark theme, an OS flip rebuilds the same `resolved` value and `commit` returns early.
- **`commit` order.** It sets `state`, then `apply()` writes the `data-theme`/`data-accent` attributes, then notifies listeners. The terminal effect therefore reads already-updated computed variables.
- **Inline script vs `parseAppearance`.** Both handle null, empty, corrupt JSON and non-object JSON (string or array) by falling back per field. Unknown values fall back per field. A missing or throwing `matchMedia` resolves to dark in both. Both read the same storage key and allowed lists, so the inline script and the store agree on first paint.
- **`ShellTerminal`.**
  - The theme effect (`[resolved, accent]`) is separate from the session effect, whose dependencies did not change, so a theme change does not restart the shell.
  - Between `new Terminal({ theme: terminalTheme() })` and `xtermRef.current = terminal` there is no `await`, so a theme change cannot slip between creation and the ref. A change before creation is already in the DOM, which creation reads.
  - Cleanup clears the ref after `dispose()`, and the cancelled-init paths cannot leave a stale ref.
  - `minimumContrastRatio` reads `resolvedRef` at creation and is reassigned live.
- **`terminalTheme.ts`.** It reads `--c-*` channel triples (`/^(\d+) (\d+) (\d+)$/`, which matches the authored single-space format), converts them to hex, and falls back to the dark literal per key. Selection is `rgba(r, g, b, a)` from `--c-term-selection` and `--a-term-selection`, with the alpha range-checked. The cursor reads `--c-accent`, so it follows the accent, as intended (U1 §3.3).
- **Specificity.**
  - `:root` is (0,1,0) and the light theme block is (0,2,0).
  - Dark accent blocks are `:root:not([data-theme="light"])[data-accent]`, at (0,3,0), and never match in light. Light accent blocks are (0,3,0) and never match in dark.
  - There is no tie in either theme, so no dark value leaks into light or the reverse, and file order is irrelevant.
- **`clusterIdentity` writes.** A guardrail toggle leaves the stored `color` byte-identical (tested), so v1.4.1 reads it back after a downgrade. An explicit pick writes the role name, and v1.4.1 then falls back to the hash default (accepted in T42-8).
- **Palette keywords.** The optional field is matched only on action entries. No other entry type changed.
- **Appearance a11y.**
  - Theme and Accent are native radio groups in `fieldset` + `legend`. Accent inputs are `sr-only` peers, so each name comes from its visible label text ("Blue" …) and the swatch is `aria-hidden`.
  - Focus shows through `peer-focus-visible:ring-accent/70`.
  - The preview is `inert` and `aria-hidden` (but see N-4).
  - "Currently …" is an `aria-live="polite"` region.
  - The write failure is `role="status"`.
  - The selected-swatch check uses `on-accent`, which is right because the selected swatch is the active accent.
- **Spot-checks of the 1b mechanical pass.**
  - All `bg-scrim/*` uses are modal or popover backdrops (CommandPalette, ConfirmModal, ContextSwitcher, ResourceEditor, HelmInstall, MergeFromFile, ResourceCreator).
  - All `text-on-accent` uses sit on `bg-accent`, apart from the decided `bg-bad/80` badge (N-1).
  - The higher-alpha tints `surface-tint/30` and `/40` are request ticks on usage bars (`DetailPanel.tsx:119`, `PodTable.tsx:52`) and `/10` is a hover (`ResourceDetailPanel.tsx:670`). All correct.
  - Remaining `bg-accent/10 text-accent` uses are buttons, toggles or decorative labels, which are accent by U1 §3.3.
