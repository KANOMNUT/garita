### 0.2 RUST-AFFECTING items

There are two. Only RA-1 changes the §2 IPC contract.

**RA-1. `start_shell_session`: close reason from the status channel, plus a client-supplied session id (§2.2, `shell.rs`). RUST-AFFECTING.**

Why (see C-3 and C-4): kube-rs `exec` resolves as soon as the WebSocket upgrade succeeds. A missing `sh` is reported afterwards, as a `Status` on status channel 3. The working-tree `shell.rs` builds `ShellClosed` from the stdout read result alone (`shell_closed_for`), so a distroless exec closes as `{ reason: "eof", message: "" }`. Also, the frontend can only `listen` after the invoke has returned the session id, so a session that closes at once emits its close event before anyone is listening. Without RA-1, F7's "no shell" recovery banner (UXP-25) has no trigger it can rely on.

This is a follow-up diff against the working-tree `shell.rs`, which already has `mode`, `ShellClosed` and `shell_closed_for`.

(a) **Close reason.**
- Call `attached.take_status()` before spawning the output task, and move the future into the task.
- After the stdout loop ends with `Ok(0)`, await that future with a bounded timeout of 2 s, then map the result:

  | Status channel result | `ShellClosed` |
  |---|---|
  | `status == "Failure"` and `reason != "NonZeroExitCode"` | `{ reason: "error", message: <status.message verbatim, "" if absent> }` |
  | `Failure` with `NonZeroExitCode`, `Success`, no status, or timeout | `{ reason: "eof", message: "" }` |

- A stdout read `Err(e)` stays `{ reason: "error", message: e.to_string() }`.
- The event is still emitted exactly once, and never after `stop_shell_session` aborts the task. An abort during the status wait emits nothing.
- Make it pure and tested: extend `shell_closed_for`, or add a sibling, to take an `Option<&Status>`. Tests:
  - `Failure` + `InternalError` gives `error` with the message
  - `Failure` + `NonZeroExitCode` gives `eof`
  - `Success` gives `eof`
  - no status gives `eof`

(b) **Client-supplied session id.**
- New signature: `start_shell_session(app, state, context, namespace, pod, container, initial_cols: u16, initial_rows: u16, mode: Option<String>, session_id: Option<String>) -> Result<String, String>`. The invoke key is `sessionId`.
- `Some(id)`: 1 to 64 characters, each in `[A-Za-z0-9_-]`. Otherwise `Err("Failed to start shell: invalid session id")`. This is validated before connecting, like `mode`.
- If the id is already in the sessions map when the session is inserted (checked under the same lock as the insert): drop the new connection and return `Err("Failed to start shell: session id already in use")`. Never overwrite an existing entry, because that would orphan its abort handle.
- `None`: today's generated `{pod}-{millis}`, with every `.` replaced by `-`. Pod names are DNS-1123 subdomains and may contain `.`, while Tauri 2 event names allow only alphanumerics, `-`, `/`, `:` and `_`.
- It returns the id it used. Event names do not change: `shell-output-{id}` and `shell-closed-{id}`.
- Pure helper with tests:
  - a valid id
  - an empty id, a 65-character id, an id with a `.`, and one with a space
  - the sanitiser on a dotted pod name

Frontend side (not Rust's job):
- `ShellSessionArgs` (`useResources.ts:1631`) gains `mode?: "exec" | "attach"` and `sessionId?: string`.
- `ShellTerminal` generates `crypto.randomUUID()`, registers both listeners **before** invoking, and unlistens if the invoke rejects.
- The §2.11 `ShellClosed` mirror does not change shape.

**Fallback if the main session declines RA-1.** F7 ships **without** the conditional "no shell" banner. The always-visible "Debug container…" in the Shell toolbar is the discovery path. The Exited card for an attach that dies at once relies on the 2 s `get_pod` poll. F7 is never blocked on RA-1.

### 0.4 Brief corrections found by the tech lead

- **C-1. R9 targets a split doc set.** See RA-2. The evidence is the staged diff and the 168-line working-tree `CLAUDE.md`.
- **C-2. The CLAUDE.md hard rule contradicts R1.** The working-tree `CLAUDE.md` hard rule says "no SSA, no strategic merge". After R1 merges that is false for `start_debug_container`. See §0.7.
- **C-3. Exec failures arrive after the upgrade.**
  - In kube-client 0.95, `AttachedProcess::new` starts the message loop once the WebSocket is open.
  - `STATUS_CHANNEL` (3) delivers a `Status` to `take_status()` (`remote_command.rs:237`, `:267`, `:308-310`).
  - So `start_shell_session` resolves `Ok` for a container without `sh`, and the server's text is discarded today.
  - This is source-read, not observed. It goes on the ledger.
- **C-4. Two event races.**
  - `ShellTerminal.tsx:56-66` registers `listen` only after `startShellSession` resolves, so a session that closes at once loses its close event. The first prompt can be lost the same way, which is part of why attach "may need an Enter".
  - Tauri 2.11 `event_name.rs:11` allows only alphanumerics, `-`, `/`, `:` and `_`, while the session id embeds the pod name, which may contain `.`.
  - Both are fixed by RA-1 (b).
- **C-5. Shell session leak on unmount during start (pre-existing).** The cleanup (`ShellTerminal.tsx:90-96`) stops only `sessionRef.current`, which is still null while the start is in flight. The async `init()` then finishes and the session runs on unseen. F7's auto-attach and §0.5's session end make this common, so F7 must fix it:
  - set a `cancelled` flag in the cleanup
  - when the start resolves on a cancelled terminal, call `stopShellSession(id)` at once
  - with RA-1, stop the pre-generated id in the cleanup too
- **C-6. `DetailPanel`'s pod is a click-time snapshot.**
  - `App.tsx:80` `selectedPod` is set from the clicked row (`PodTable.tsx:480`) and passed unchanged (`App.tsx:516-518`).
  - The pods poll never refreshes it, so `pod.status` (the Q-L10 gate) and `pod.ephemeral_containers` (the `[debug]` rows) go stale.
  - F7 reads these from `get_pod` query data, falling back to the matching row of App's pods list (pass it as an extra prop), and then to the snapshot.
  - **Do not** change what `LogViewer` and `ShellTerminal` receive. A new object identity on every poll would re-run container pre-selection and could restart streams.
- **C-7. The eviction hint is per namespace (F4).** Drain spans namespaces, and the node gate is `usePermissions(context, "", "nodes")` (`ResourceDetailPanel.tsx:379`). A single cluster-wide `create pods/eviction` check would wrongly deny a user who may evict in each relevant namespace.
  - After the preview, issue one batched `can_i` with one check per distinct namespace among `category == "evict"` pods (`k8s.ts:880-882`).
  - Denied namespaces produce a review warning line: "Your account can't evict pods in {namespaces}. Those evictions will fail."
  - It never disables Drain, and it fails open.
  - Use a small dedicated hook. Do not widen `Permissions` or `usePermissions` (`useResources.ts:1517`), which are keyed by `ResourceType` and have no subresource. The F7 `pods/ephemeralcontainers` gate uses the same hook.
- **C-8. Backstop shape (F4).** The read-only check lives in **one** helper in `useResources.ts` that every write `invoke` goes through. The property is then greppable: each write command name appears only inside that helper's call sites.
  - Writes outside a plain `useMutation` must be included too: `startShellSession` (`useResources.ts:1640`), `useEvictPod` (`:658`) and the bulk deletes.
  - `writeToShell`, `resizeShell` and `stopShellSession` are **not** guarded. They act on an already-open session, and §0.5 ends those sessions instead.
  - The F4 handback list remains the acceptance record.
- **C-9. Q-L9 parsing.** `server_version` is the API server's `git_version` (`cluster_info.rs:286`), for example `v1.29.3-gke.100` or `v1.27.4+k3s1`. Parse it with `^v?(\d+)\.(\d+)`. Anything else fails open.
- **C-10. Per-container exec (optional).** The per-container "exec" (`DetailPanel.tsx:754`) switches to the Shell tab without selecting that container. This is pre-existing. While touching the button for D3-7, select the container first. It is not required.

### 0.5 Decision: an open shell when read-only turns on (UXP-20)

**USER DECISION (confirmed by the user on 2026-10-04): turning read-only on ends every open shell or attach session for that cluster.**

- **Why.** D3-7 says shells are blocked while read-only. An open interactive shell is the most capable write path in the app. Leaving it alive would make the badge's "Pod shells are blocked." false the moment it appears.
- **Mechanism (frontend only, no Rust).**
  - `useClusterIdentity` already notifies in-process (`clusterIdentity.ts:89-111`).
  - When read-only turns on, the Shell tab renders its disabled state in place of `ShellTerminal`. The unmount runs the existing cleanup, which calls `stop_shell_session`.
  - The tab then shows: "Shell closed: read-only mode was turned on for {label}. Turn it off to open a shell."
  - A debug container keeps running in the pod, because it cannot be removed. The strip shows Detached, with Attach disabled for the read-only reason.
- **Scope.** Port-forward and log streams are not affected. `writeToShell` gets no guard (C-8).
- **One switch.** The session end keys off `READ_ONLY_BLOCKS_SHELL` like the rest of D3-7. With the constant `false`, neither the block nor the session end applies.

```rust
    pub api_version: String, pub kind: String,
    pub namespace: String,  // metadata.namespace, else the release namespace
    pub name: String,
    pub change: String,     // "new" | "changed" | "removed" | "unchanged"

    pub new_values: serde_json::Value,        // values_yaml parsed; "" → {}; Null when invalid

```

Sequence:
1. Parse `values_yaml`. On failure, return `outcome "invalid"`.
2. `helm get values … -o json`.
3. `extract_chart_from_k8s`. This is the **same** release-secret path upgrade uses; never a repo lookup.
4. `helm upgrade <release> <chart_dir> --values <tmp> --namespace <ns> --kube-context <ctx> --dry-run -o json`, with separate `.arg()`s. Parse `.manifest`.
5. `helm get manifest <release> -n <ns> --kube-context <ctx>`.
6. Run the pure, unit-tested `diff_manifests(current: &str, rendered: &str, default_ns: &str) -> Result<Vec<HelmRenderedResource>, String>`.

`diff_manifests`:
- It splits documents with **`split_yaml_documents` from `apply_file.rs`**, made `pub(crate)`. Never split on `---`, and never use a `serde_yaml` iterator chain (the multi-doc hang).
- Empty or comment-only docs are skipped.
- Each resource is keyed by `(kind, namespace-or-default, name)`, and values are compared with `serde_json::Value` equality.
- A parse error → `Err`, which the command reports as `outcome "rejected"`.

| Situation | Result |
|---|---|
| The helm binary is not runnable, `friendly_auth_error` matches stderr, chart extraction fails, or client errors | `Err(...)` with the existing friendly text (= `unavailable`) |
| The dry run exits non-zero for any other reason | `Ok` with `outcome "rejected"` |
| The dry run's stdout is not JSON | `Err("Failed to preview upgrade: unexpected helm output: {e}")` |
