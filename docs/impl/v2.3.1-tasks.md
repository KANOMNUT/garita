### 3.1 F1: `src/utils/tableRows.ts` (new) and `GenericResourceTable` props

```ts
export interface SortState { col: string; asc: boolean }
/** Structural subset of Column<T> (GenericResourceTable.tsx:10-17). */
export interface SortableColumn<T> { id: string; sortValue?: (item: T) => string | number }
/** Exactly the predicate at GenericResourceTable.tsx:117-123: no search (undefined or "") returns `data`. */
export function searchRows<T>(data: readonly T[], search: string | undefined, keyFn: (item: T) => string): T[];
/** Exactly the comparator at GenericResourceTable.tsx:125-139: numbers numerically, else localeCompare; null sort keeps the order. */
export function sortRows<T>(rows: readonly T[], columns: readonly SortableColumn<T>[], sort: SortState | null): T[];
/** sortRows(searchRows(...)): the rows the table shows, in its order. */
export function shownRows<T>(data: readonly T[], search: string | undefined, keyFn: (item: T) => string, columns: readonly SortableColumn<T>[], sort: SortState | null): T[];
/** Checkbox click. `shift` with an anchor in `order`: set or clear every key from anchor to key (set when key was not selected). Otherwise toggle key. Never adds a key that is not in `order`. */
export function rangeSelect(prev: ReadonlySet<string>, order: readonly string[], anchor: string | null, key: string, shift: boolean): Set<string>;
```

`GenericResourceTable` gains two optional props, so every other caller compiles and behaves as today:

```ts
/** Controlled sort. When `onSortChange` is given, the table shows `sort` and reports header clicks instead of keeping its own state. */
sort?: SortState | null;
onSortChange?: (sort: SortState | null) => void;
```

The table computes its rows with `searchRows` and `sortRows` (the inline code moves into the helpers unchanged). `ArgoCDView` holds `sort` state, passes `sort`/`onSortChange`, and derives one array, `shown = shownRows(filtered, search, argoKey, argoColumns, sort)`, where `argoKey` is a module-level function returning `namespace/name` (the string the inline `keyFn` returns today, ResourceViews.tsx:1899), also passed as the table's `keyFn`. Select all is `new Set(shown.map(argoKey))`; shift-range is `rangeSelect(prev, shown.map(argoKey), lastChecked, key, shift)`; `selectedApps = shown.filter(selected)`; the bulk bar's presence and its "N selected" use `selectedApps.length` (not `bulkSelected.size`, which can count an app a refetch removed). The selection still clears on a health-filter or search change (ResourceViews.tsx:1775-1778), not on a sort change.

Rules the component owns: the root `<div>` carries the one `onKeyDown` (UX 22 §4.4: `shortcutMatches`, `!isModalOpen()`, `root.contains(e.target)`; Esc closes the bar and calls `stopPropagation()`); no `window` or `document` listener; no modal layer; the `<pre>` is `tabIndex={0}` `role="region"` with `aria-label={regionLabel}` (D7); the textarea keeps `spellCheck={false}` plus `autoCorrect`, `autoCapitalize` and `autoComplete` off (this fixes the Pod textarea, F7); the caller's `onKeyDown` (⌘S, the review gate) still runs on the textarea. Matching runs on `useDeferredValue(query)`. The query lives in component state only (S3). One `role="status"` live region, debounced 500 ms for counts (S4).

Each surface renders **one** `<YamlFind>` element whose `edit` prop switches between read and edit, so the bar survives the switch (UX 22 §4.6 item 8). The skeleton and the Secret placeholder branches stay outside it (C-6).
