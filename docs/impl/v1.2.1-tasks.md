**Why D1-4 is the engine fix and not the rename.** Today the History tab keeps only the first 7 characters of `status.history[].revision` (`argocd.rs` ~line 747) and sends that truncated string as the sync `revision`. For a Helm-chart source, `10.11.12` becomes `10.11.1`, which is a different, wrong version and not a short SHA. Renaming the button would still ship a button that syncs the wrong revision, so a backend change is needed either way. A rollback command keyed by history id is the smallest safe change. It reads the full revision and source server-side, mirrors upstream `Rollback`, and is unit-testable with no cluster.

**Overrides of the UX copy and design (tech lead, adopted):**

1. **Complete-drain cordon line.** "Evicted" means the eviction was *accepted* (HTTP 2xx); the pod then terminates within its grace period. UX's "Node is cordoned and empty." over-claims. Use: **"Node is cordoned. Evicted pods stop within their termination grace period. Uncordon when maintenance is done."** Incomplete, stopped and paused keep UX's line: "Node remains cordoned. Uncordon to return it to service."
2. **New outcome `gone`** (HTTP 404 on eviction: the pod was already deleted). Count it separately as "{n} already gone" and show it only if non-zero. **Never fold it into "evicted".** Row: glyph `✓`, word "Already gone", role `dim`.
3. **New preview field `has_empty_dir`.** Under the unmanaged warning, show one warning line when any pod to evict has it: **"{n} pod(s) use emptyDir volumes. That data is deleted when they are evicted."** It does not trigger the typed confirm.
4. **P5: no "State A" copy and no "auto-sync may sync forward" line.** When `auto_sync` is true, the row button is disabled, with this reason: **"Auto-sync is on. ArgoCD doesn't allow a rollback while auto-sync is enabled. Turn off auto-sync first."**
5. **Persistent result card** (UX §2.10): ships. **Force-delete nested dialog** (UX §2.8): does not ship (D1-3).
6. **"Retry blocked pods" retries `blocked` pods only.** `failed` pods stay failed. "Resume drain" (Stopped outcome) re-opens `review` with a fresh preview.

## 2. FROZEN IPC contract

**Naming rule.** Struct fields are snake_case on **both** sides: there is no `#[serde(rename_all)]`, so TS interfaces use the same snake_case names. **Command arguments** are converted by Tauri v2: a Rust `snake_case` param becomes a `camelCase` key in the `invoke()` object. Both columns are listed for every command.

String "enums" are closed sets. Rust emits exactly these literals, and TS types them as literal unions.

### 2.1 `preview_node_drain` (new, `src-tauri/src/commands/drain.rs`)

| | |
|---|---|
| Rust | `pub async fn preview_node_drain(context: String, node: String) -> Result<DrainPreview, String>` |
| invoke | `invoke<DrainPreview>("preview_node_drain", { context, node })` |
| Side effects | **None.** A `GET` on the node, a `LIST` of pods with `fieldSelector=spec.nodeName=<node>` (`Api::all`), and a `LIST` of `policy/v1` PDBs **per distinct namespace** among those pods (`Api::namespaced`, `join_all`). |

```rust
#[derive(Serialize, Deserialize, Debug, Clone)]
pub struct DrainPdbRef {
    pub name: String,
    pub disruptions_allowed: i32,   // pdb.status.disruptions_allowed; 0 when status is None
}

#[derive(Serialize, Deserialize, Debug, Clone)]
pub struct DrainPodPreview {
    pub namespace: String,
    pub name: String,
    pub category: String,           // "evict" | "daemonset" | "mirror"
    pub owner_kind: Option<String>, // see rules below; None when unmanaged
    pub owner_name: Option<String>,
    pub unmanaged: bool,            // no ownerReference with controller == Some(true)
    pub has_empty_dir: bool,        // any spec.volumes[].empty_dir.is_some()
    pub pdbs: Vec<DrainPdbRef>,     // every PDB in the pod's namespace whose selector matches the pod's labels
    pub may_be_blocked: bool,       // category == "evict" && pdbs.iter().any(|p| p.disruptions_allowed <= 0)
}

#[derive(Serialize, Deserialize, Debug, Clone)]
pub struct DrainPreview {
    pub node: String,
    pub unschedulable: bool,            // node.spec.unschedulable.unwrap_or(false)
    pub node_ready: bool,               // Ready condition == "True"
    pub pods: Vec<DrainPodPreview>,     // EVERY pod on the node, sorted by (namespace, name)
    pub pdb_lookup_errors: Vec<String>, // one entry per namespace whose PDB list failed
}
```

Classification rules (each one is a pure function with unit tests, see R2):

| Rule | Exact behaviour |
|---|---|
| `category = "mirror"` | `metadata.annotations` contains the key `kubernetes.io/config.mirror`. This is checked first. |
| `category = "daemonset"` | The controller ownerReference (`controller == Some(true)`) has `kind == "DaemonSet"`. |
| `category = "evict"` | Everything else, including unmanaged pods, completed (Succeeded/Failed) pods and terminating pods. |
| `unmanaged` | `true` when there is no ownerReference with `controller == Some(true)`. Mirror pods are reported `unmanaged: false` (they are skipped anyway). |
| `owner_kind` / `owner_name` | From the controller ownerReference. **Exception:** if the kind is `ReplicaSet`, the pod has label `pod-template-hash = H`, and the RS name ends with `-H`, report `("Deployment", rs_name minus "-H")`. Otherwise report the raw controller kind/name (for example `("ReplicaSet", "foo-abc")`). `None`/`None` when unmanaged. No extra API call. |
| PDB selector match | `spec.selector == None` matches **nothing**. `Some({})` (empty matchLabels and matchExpressions) matches **every** pod in the namespace. `matchLabels` must all be equal. `matchExpressions` operators are `In`, `NotIn`, `Exists`, `DoesNotExist`; an unknown operator does not match. This is display-only: the API server enforces the real check. |
| `pdb_lookup_errors` entry text | `format!("Failed to list PodDisruptionBudgets in {}: {}", ns, e)`. Pods in that namespace get `pdbs: []` and `may_be_blocked: false`. The preview still returns `Ok`. |

Errors (`Err`), verbatim:

| Situation | Text |
|---|---|
| Client construction | `Failed to connect: {e}` |
| Node GET fails (including 404) | `Failed to get node: {e}` |
| Pod list fails | `Failed to list pods on node: {e}` |

### 2.2 `evict_pod` (new, `drain.rs`)

| | |
|---|---|
| Rust | `pub async fn evict_pod(context: String, namespace: String, name: String) -> Result<EvictionResult, String>` |
| invoke | `invoke<EvictionResult>("evict_pod", { context, namespace, name })` |
| Behaviour | `Api::<Pod>::namespaced(..).evict(&name, &EvictParams::default())`. **Never calls `delete`.** There is no fallback of any kind. |

```rust
#[derive(Serialize, Deserialize, Debug, Clone)]
pub struct EvictionResult {
    pub namespace: String,
    pub name: String,
    pub outcome: String,   // "evicted" | "blocked" | "gone" | "failed"
    pub message: String,   // "" for "evicted"; otherwise the server message verbatim (ErrorResponse.message, or e.to_string() for non-API errors)
}
```

Classification is a pure function, `classify_eviction_error(code: u16, message: &str) -> &'static str`:

| Condition | outcome |
|---|---|
| `Ok(_)` from `evict` | `"evicted"` (the eviction was **accepted**, and the pod is now terminating) |
| `kube::Error::Api`, code 429, and `message.to_lowercase()` contains `"disruption budget"` | `"blocked"` |
| `kube::Error::Api`, code 404 | `"gone"` |
| Anything else, including a 429 without that phrase (APF throttling) and the 500 "multiple PDBs" error | `"failed"` |
| Any non-`Api` kube error (transport, TLS, timeout) | `"failed"`, with `message = e.to_string()` |

`Err` is returned **only** when `client_for_context` fails: `Failed to connect: {e}`. The frontend treats a rejected `evict_pod` invoke as a `failed` row whose message is the error string.

### 2.4 `rollback_argocd_app` (new, `src-tauri/src/commands/argocd.rs`)

| | |
|---|---|
| Rust | `pub async fn rollback_argocd_app(context: String, namespace: String, name: String, history_id: i64) -> Result<String, String>` |
| invoke | `invoke<string>("rollback_argocd_app", { context, namespace, name, historyId })` |
| Behaviour | Resolve the group version via `argo_api_resource` and `GET` the Application. Then `build_rollback_patch(&app_json, history_id)`, a pure function. Then `Patch::Merge`. |

`build_rollback_patch(app: &serde_json::Value, history_id: i64) -> Result<serde_json::Value, String>` mirrors upstream `server/application.Rollback`. It checks guards in this order, and the first failing guard returns `Err`:

1. `app["operation"]` is not null → `Failed to roll back: another operation is already in progress`
2. Auto-sync is enabled → `Failed to roll back: rollback cannot be initiated when auto-sync is enabled`. "Enabled" means `spec.syncPolicy.automated` is a JSON object **and** `automated.enabled` is not `false`. The pure function `auto_sync_enabled(&app["spec"])` is shared with the list path.
3. No `status.history[]` entry has `id == history_id` → `Failed to roll back: application {name} does not have deployment with id {history_id}`
4. The entry has neither a non-empty `source` object nor a non-empty `sources` array → `Failed to roll back: cannot rollback to revision deployed with Argo CD v1.4 or older`

The patch it returns, exactly:

```json
{ "operation": {
    "sync": {
      "revision": "<entry.revision>",   "source": <entry.source>,        // single-source entry
      // OR, when entry.sources is a non-empty array:
      "revisions": <entry.revisions>,  "sources": <entry.sources>,      // multi-source entry
      "prune": false,
      "dryRun": false,
      "syncStrategy": { "apply": {} },
      "syncOptions": <spec.syncPolicy.syncOptions>                       // ONLY if a non-empty array
    },
    "initiatedBy": { "username": "watchtower" } } }
```

- **This is the only sanctioned use of `syncStrategy.apply` in the codebase. It is there for upstream parity:** upstream `Rollback` sets `SyncStrategy{Apply: {}}`, which skips hooks. `sync_argocd_app` keeps `syncStrategy.hook.force`. Neither may be "aligned" to the other.
- There is never a `force` key anywhere, and never `operation.sync.force`.
- The `name` used in guard 3's message is `app["metadata"]["name"]`, falling back to `""`.
- Other errors: not installed → `Failed to roll back: ArgoCD is not installed on this cluster`. GET or patch failure → `Failed to roll back: {e}`. Success `Ok` text → `Rollback to history id {history_id} initiated for {name}`.

- **Run sequence:**
  1. If the snapshot `unschedulable` is false, call `cordon_node`. On error, go to phase `error` with "Couldn't cordon {node}: {message}. No pods were evicted. …" (UX §2.11). If it is already cordoned, the step shows "Already cordoned".

  3. Targets are the fresh preview's `category === "evict"` pods.
  4. Run `evict_pod` **sequentially**. Before each one, check a Stop ref. The in-flight call completes. A rejected invoke becomes `failed` with the error string.
  5. After the pass: any `blocked` → `attention`; else → `result`.
  6. "Retry blocked pods" re-runs step 4 over the `blocked` pods only. Increment the attempt counter. Per-pod state is the latest outcome.
  7. On reaching `attention` or `result`, invalidate `["nodes", context]`, `["node-pods", context, node]` and `["pods", context]`.
