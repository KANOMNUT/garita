**(a) R1 amendments: commit 1, with F1, alone and first.** The shipped R1 is ratified as it stands: `sizes` from the decoded `ByteString`; `helm get values -o yaml`; `null` or empty → `""` on both paths; `HELM_REDACT_KEYS` in `helm.rs`, separate from `SCRUB_KEYS`; `reject_redacted` serving both guards with the §2.2 strings. Four additions:

- **R1-a. Mask Secret documents in the Helm rendered manifest (B-5, P17).** `preview_helm_upgrade` passes `rendered_manifest` through a pure, tested `mask_rendered_secrets(manifest: &str) -> String`:
  - Split with `split_yaml_documents`, as a loop that breaks on the first error.
  - In every `kind: Secret` document, replace each `data` and `stringData` value with `HELM_REDACTION_SENTINEL`.
  - Re-serialise the documents, joined by `---\n`.
  - Any parse error returns the fixed line `# The rendered manifest could not be parsed for masking.` and never the raw text.
  - `resources`, `current_values` and `new_values` are unchanged. The values are reachable only after a reveal.
  - Tests: a Secret document is masked; a ConfigMap is untouched; a malformed document returns the fixed line without hanging.
- **R1-b. A list of scalars under a credential key is redacted.** Today `apiKeys: [k1, k2]` passes unredacted. A sequence is recursed, but its scalars are not under a key, so `redact_value` skips them. The rule becomes: a scalar is redacted when its nearest enclosing mapping key matches, and a sequence passes that key down to its elements. Maps inside the sequence still recurse with their own keys, so `imagePullSecrets: [{name: regcred}]` keeps `regcred`. Test: `apiKeys: [k1, {name: n}]` gives the sentinel for `k1` and keeps `n`.
- **R1-c. Secret last-applied annotation in `get_resource_metadata` (`extras.rs`; freeze audit, B-5).** For `sec` / `secret`, replace the value of `kubectl.kubernetes.io/last-applied-configuration` with the sentinel text `<redacted by Watchtower>`. Keep the key, so its presence still shows. Other kinds are unchanged. The Metadata tab renders every annotation of the object it fetches, so today a `kubectl apply`'d Secret shows its values with no reveal. Factor this into a pure, tested helper.
- **R1-d. Helm install dry run (`install_helm_release`; freeze audit, B-5).**
  - When `dry_run == Some(true)` and helm succeeds, return the fixed line `Dry run succeeded. The rendered manifest isn't shown because it can contain Secret values.` instead of helm's stdout.
  - Errors stay as they are.
  - The line contains "dry run", so `HelmInstallModal`'s `includes("dry run")` check keeps passing.
  - Test the string selection as a pure function.

| Possibly unused | No false positive for a ConfigMap referenced only by a CronJob template, a projected volume, or an init container. |
| Deprecated APIs | A Helm release with a removed API on a cluster one minor behind and one ahead; served-version discovery. |

## 8. Risks

| Risk | Mitigation |
|---|---|
| Removing `Secret.data` breaks a consumer `tsc` cannot see (a `Record<string,string>` read through `any`) | F1 lands alone; the handback lists every consumer; live row 1. |
| The Helm redaction re-serialises YAML, losing comments and ordering in the **read-only** view | Stated in the view ("Comments are not shown in the redacted view"). The edit view is the revealed original text. |
| Who-can answers look authoritative on clusters with cloud IAM mappings | The non-RBAC note is always shown; copy never says "only these subjects". |
| `scan_deprecated_apis` cost on clusters with many Helm releases | On-demand only (no interval); decode is in-process, no Helm shell-outs. |
