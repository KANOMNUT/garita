**Ground rules (deltas from `CLAUDE.md`)**

- **New dependencies, this release only:** `tauri-plugin-updater` and `tauri-plugin-process` (crates), and `@tauri-apps/plugin-updater` and `@tauri-apps/plugin-process` (npm). The pins are in T21-6. Removed: `tauri-plugin-shell` (unused, no capability).
- **macOS signing stays ad-hoc.** The updater signature (minisign, `tauri signer`) has nothing to do with Apple code signing. Never add `--options runtime`, Developer ID or notarization.
- **The update check is non-blocking and quiet on failure.** No modal and no toast. Automatic checks fail silently.
- **Not a cluster write.** Read-only mode does not affect updates. No `invokeWrite`.

### 1.5 User actions

**U1. Updater signing key (Q50-1). This clears DRAFT. Do it once, on a trusted machine. Never regenerate it.**

1. Generate the key with a password. The CLI prompts for it; do not pass `-p`, so the password stays out of shell history.
   - PowerShell, from the repo: `npx tauri signer generate -w "$env:USERPROFILE\.tauri\garita-updater.key"`
   - This writes `garita-updater.key` (private) and `garita-updater.key.pub` (public).
2. Back up **both the key file and its password** in two places, for example the password manager (with the key file attached) and an offline USB. **If either is lost, no installed copy can ever auto-update again.** The only recovery is a manual reinstall of a build with a new pubkey.
3. Create a GitHub Environment `release`: Settings → Environments → New → `release` → Deployment branches and tags → *Selected* → add the tag rule `v*`. Required reviewers are optional.
4. Store both values as **environment** secrets (not repository secrets):
   - Git Bash (not PowerShell: a pipe appends CRLF and breaks the key): `gh secret set TAURI_SIGNING_PRIVATE_KEY --env release -R KANOMNUT/garita < ~/.tauri/garita-updater.key`
   - `gh secret set TAURI_SIGNING_PRIVATE_KEY_PASSWORD --env release -R KANOMNUT/garita` (interactive prompt only)
   - Until the rename (U2), use `-R KANOMNUT/watchtower`; environments and secrets move with the rename.
5. Paste the **contents of `garita-updater.key.pub`** into the session. It is public. rust-engineer commits it as `plugins.updater.pubkey` (R1).
6. Never commit the `.key` file. It lives outside the repo.
7. Hardening additions (S1):
   - Use a random password of 24+ characters.
   - Record the key ID (`8ca87849178bcf25`; `.pub` comment `25CF8B174978A88C`) and put it in `EXPECTED_KEY_ID` in `release.yml` (Prepare job), so a wrong pubkey fails before the build.
   - Delete the local `.key` after the two backups exist.
   - Environment `release`: required reviewer KANOMNUT, admin bypass off, tag rule `v*`. Once public: tag ruleset on `refs/tags/v*` and immutable releases.
   - Hardware 2FA; no classic PAT with `repo` scope.
   - Rotation and leak response: `docs/build-and-release.md` → In-app updater → Key custody.

export type UpdatePhase = "check" | "download" | "install";
export type UpdateState =
  | { s: "unavailable" }                                   // dev build
  | { s: "idle" }                                          // not checked yet
  | { s: "checking" }
  | { s: "up-to-date"; checkedAt: number }
  | { s: "available"; version: string; notes: string; checkedAt: number }
  | { s: "downloading"; version: string; received: number; total: number | null }
  | { s: "ready"; version: string }
  | { s: "installing"; version: string }

export function useAppUpdate(): {

## 3. `release.yml` step order (R2)

**build job, macOS leg.** "Build installers" is unchanged: no secrets, no `createUpdaterArtifacts`. Then, in order:

1. `codesign --sign - --deep --force "$app"` (existing).
2. **New:** `codesign --verify --deep --strict "$app"`.
3. **New:** create the tarball from the **signed** app:
   - `COPYFILE_DISABLE=1 tar -C "$bundle/macos" -czf "$bundle/macos/Garita.app.tar.gz" "$(basename "$app")"`
   - It must have exactly one top-level entry, `Garita.app/`, because the plugin drops the first path component (E2). It must have no `._*` AppleDouble entries.
4. **New:** self-check the tarball, failing the job on any miss:
   - `tar -tzf "$tgz" | cut -d/ -f1 | sort -u` is exactly `Garita.app`.
   - `! tar -tzf "$tgz" | grep -q '/\._'`.
   - Extract to a temp dir, then `codesign --verify --deep --strict <tmp>/Garita.app`.
5. Recreate the DMG from `"$app"` (existing; it now runs after the tarball, from the same signed app).
6. Collect step: add `pick macos "*.app.tar.gz" Garita-macOS-arm64.app.tar.gz`.

**build job, Linux leg:** no change. The `.deb`/`.rpm` are the updater artifacts.

**publish job.** Add `environment: release` to the job. Then, in order:

1. **New, first:** `actions/checkout` of `refs/tags/$TAG` (`persist-credentials: false`), then `actions/setup-node` (no cache), then `npm ci --ignore-scripts`. Checkout must come **before** the downloads, because checkout cleans the workspace. This supplies the lock-pinned tauri CLI and `tauri.conf.json`.
2. Download `installers-*` → `dist`, and `release-meta` → `meta` (existing).
3. **New: "Sign updater files".** This is the **only** step with `env: TAURI_SIGNING_PRIVATE_KEY: ${{ secrets.TAURI_SIGNING_PRIVATE_KEY }}` and `TAURI_SIGNING_PRIVATE_KEY_PASSWORD: ${{ secrets.TAURI_SIGNING_PRIVATE_KEY_PASSWORD }}`. Never echo the secrets, and no `set -x`.
4. **New: "Check signing key" (fail closed).** For each `.sig`: base64-decode, take line 2, base64-decode that, and read bytes 2..10 (the minisign key ID). Compare it with the same bytes from `plugins.updater.pubkey` in `tauri.conf.json`. Also assert that line 3 of the decoded `.sig` (the trusted comment) holds the field `version:X.Y.Z`. On a mismatch, or a pubkey or `.sig` that does not decode (e.g. `PENDING_U1_PUBKEY`), `::error::` and exit 1. tauri-cli only warns on a mismatch (E3), and a mismatch would strand every 2.1.0 install.
5. **New: "Write latest.json"** with `jq -n` (`--rawfile` for the notes and the three sigs) per §2.4, into `dist/latest.json`. Assert: three platforms, and every `url` starts with `https://github.com/KANOMNUT/garita/releases/download/$TAG/` and names a file in `dist/`.
6. Checksums (existing). These now cover the tarball, the `.sig` files and `latest.json`.
7. Attest build provenance (existing). Covers the same files.
8. Create or update the draft (existing). `--clobber` re-runs regenerate the signatures and `latest.json` consistently.

## 7. Risks

| Risk | Mitigation |
|---|---|
| Lost key: no install can ever auto-update | U1 steps 2 and 6; the R4 doc statement. |
| Leaked key | Environment secret with a tag rule. Used in one step of one job, never in builds. An attacker would also need write access to the repo's releases. |
| Key/pubkey mismatch ships | The fail-closed key-ID check (§3 publish step 4). |
| Tarball holds the pre-codesign app, or a bad layout | The tarball is made after codesign from the same `.app` as the DMG. The layout and `codesign --verify` self-checks run in CI. |
| Linux bundle type not patched → Linux check fails | L3 catches it before 2.1.1. It is a notice-only failure, nothing is installed. |
| An older-line publish hijacks `latest` | T21-14 note in `build-and-release.md`. |
| Endpoint 404 (repo private or not renamed) | U2 before the tag. Automatic checks are silent; manual checks point at the release page. |
