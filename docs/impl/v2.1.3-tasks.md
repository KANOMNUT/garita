| # | Decision | Reason |
|---|---|---|
| K1 | **The Windows updater shows a notice, as Linux does.** `src-tauri/capabilities/updater-macos.json` is unchanged, so in-app install stays macOS-only. `updateMode()` in `src/utils/updateState.ts` returns `"notice"` for Windows. `latest.json` still gets signed `windows-x86_64-nsis` and `windows-x86_64-msi` entries, because `check()` fails with `TargetNotFound` when the running platform has no key. | K2 | **Linux needs no post-install or post-remove scripts.** `/usr/bin/garita` is the binary itself. T52-3 is dropped. | A1 binary row |
| K3 | **macOS:** Settings → Command line creates `/usr/local/bin/garita` pointing at the canonicalised `current_exe()` (`…/Garita.app/Contents/MacOS/garita`). The cask gets `binary "#{appdir}/Garita.app/Contents/MacOS/garita"`; the target defaults to `garita`. Homebrew links into its own prefix (`/opt/homebrew/bin` on Apple Silicon), so the UI shows `resolved_path` and never a hard-coded path. | T52-4 kept, with the names fixed |
| K4 | **Windows PATH, by installer.** NSIS uses Tauri's default `installMode` (currentUser, no admin) and adds `$INSTDIR` to the user PATH (`HKCU\Environment`) through `installerHooks`. MSI uses Tauri's `main.wxs` (`InstallScope="perMachine"`, needs admin) and adds `[INSTALLDIR]` to the system PATH through a WiX fragment `<Environment Name="PATH" Part="last" System="yes" Permanent="no" Action="set">`. Windows Installer removes that entry on uninstall. | T52-5's "per-user, no admin" only ever held for NSIS. A per-machine MSI that writes one user's PATH would leave an orphaned entry. |
| K5 | **NSIS PATH guard (prevents data loss).** Tauri's NSIS 3.11 has `NSIS_MAX_STRLEN=1024` (confirmed with `makensis -HDRINFO` on the dev box) and ships no EnVar plugin. The hook never writes a PATH it did not read in full, and never builds one that does not fit. If `ReadRegStr` sets the error flag, it leaves PATH untouched and says why with `DetailPrint`. It adds the entry only when `StrLen(PATH) + 1 + StrLen($INSTDIR)` is below 1000, which leaves a margin under 1024 because the guard is on the combined result: a short PATH plus `;$INSTDIR` can still overflow and get truncated silently. It adds the entry only when that exact entry is absent (case-insensitive, `;`-delimited), and removes only that exact entry. Removal only shrinks the string, so it is safe once the value was read in full. It writes back with `WriteRegExpandStr` to keep `REG_EXPAND_SZ`, then broadcasts `WM_SETTINGCHANGE` with `STR:Environment` and a timeout. The length cap carries a `ponytail:` comment. | Writing back a truncated or empty PATH destroys the user's PATH. Known limit: a long user PATH gets no command, and Settings shows the folder to add (A5). If that limit bites, the upgrade is for the app to edit the registry itself, which has no length limit. |
| K6 | **Launch args are pulled, not pushed.** The single-instance callback stores the parsed `LaunchArgs` in a pending slot (latest wins). It then emits `launch-args` with a `null` payload, unminimises the window and focuses it. `get_launch_args` returns the pending slot if one is set, and then counts the first instance's own argv as consumed. Otherwise it returns its own argv once, and `LaunchArgs::default()` after that. The frontend registers its `launch-args` listener **before** its first `get_launch_args` call, and pulls on every event. | e8de6b8 emits the payload with no buffer, so a second invocation during startup, before the listener exists, is lost. This model has one source, loses nothing and never applies twice on a webview reload. It implements UX-13 #9's last row. |
| K7 | `ns`, `namespace(s)` and `crd-instances` stay unmapped, so a typed `ns` goes to `ignored`. The help's short-name line leaves `ns` out (`HELP_SHORT_NAMES`). | There is no namespaces `ResourceType`, and a new view is out of scope. Overrides `ns` in T52-1 and in UX-13 #12's help line. UX-13 #12's test that every name in the help resolves stays (it exists: `help_names_resolve_and_caps`). |
| K8 | **Parser semantics follow UX-13 #1 and #2 as relayed; e8de6b8 already implements them.** `-nfoo` goes to `ignored`. `-n=x`, `--namespace=x` and `--context=x` are accepted. A value flag with no value puts the flag token in `ignored`. Second and later positionals go to `ignored`. `-psn_*` is dropped silently. Values of consumed flags never appear in `ignored`. Every `ignored` token and every stderr echo is capped at 64 characters plus `...`. `--help` beats `--version`, which beats a normal run. The launching process prints the stderr lines before it detaches, and only when stderr is a terminal. Windows prints none. | Confirmed. |
| K9 | Rust does **not** cap context or namespace values. Real context names run past 64 characters (`gke_<project>_<zone>_<cluster>`, EKS ARNs). The frontend caps them for display only, in strip lines. | Capping in Rust would break matching. |
| K10 | **Namespace validation fails open.** If the target context's namespace list errors or is forbidden, the namespace is applied as typed, with no strip line. | Many users cannot list namespaces. This follows the same spirit as `can_i` failing open. |
| K11 | **`install_cli_command` is app-local.** It takes no `context` param and is called with a raw `invoke` in `useResources.ts`. It gets an `EXEMPT` entry in `src/hooks/writeBackstop.test.ts`: "local symlink in /usr/local/bin, not a cluster write; works read-only". | `WRITE_VERBS` matches `install_`, so without that entry the backstop test fails. Overrides UX-13 #6 "must not list it". |
| K12 | **macOS `install_cli_command` refuses a temporary location.** A temporary location means the canonicalised exe is under `/AppTranslocation/`, or sits on a read-only volume (a mounted DMG). An Applications folder on a writable external volume is fine. In those cases it returns `Err("Failed to install command: Garita is running from a temporary location. Move Garita to Applications, reopen it, and try again.")`. It also canonicalises the exe so that a launch through the link never produces a link to itself. | Otherwise the link dangles once the app quits or the DMG is ejected. |
| K13 | **Scoop uses the MSI.** Scoop extracts MSIs natively, so no installer runs and no PATH hook fires; Scoop's `bin` shim provides `garita`. `site/scoop/garita.json` is committed as valid JSON with placeholder version and hash. `pages.yml` fills it in with `jq` from the latest release, using `gh release view` for the tag and `gh release download -p SHA256SUMS.txt` for the hash, with `GH_TOKEN: ${{ github.token }}` and no new action. ### A5. Contract (frozen)

`LaunchArgs` and `LaunchAction` stay as in e8de6b8 (`src-tauri/src/launch.rs`). The TS `LaunchArgs` and `CliStatus` stay as in ffec987 (`src/types/k8s.ts`). No command takes a new or optional param, so the `Option<T>` rule is not triggered.

| Rust (app-local, no `context`) | JS | Notes |
|---|---|---|
| `get_launch_args() -> Result<LaunchArgs, String>` | `invoke<LaunchArgs>("get_launch_args")` | K6. `LaunchArgs::default()` means there is nothing to apply. |
| event `launch-args`, payload `()` (serialises as `null`) | `listen<null>("launch-args", pull)` from one `useResources.ts` helper, registered once, before the first pull | A ping only. This is an app-lifetime listener, not a log stream; `launcher.md` records why it does not conflict with the log-stream rule. |
| `get_cli_status() -> Result<CliStatus, String>` | `invoke<CliStatus>("get_cli_status")` | |
| `install_cli_command() -> Result<CliStatus, String>` | `invoke<CliStatus>("install_cli_command")`, a raw `invoke` with an `EXEMPT` entry (K11) | macOS only. Every other OS gets `Err("Failed to install command: not supported on this platform")`. |

`CliStatus` maps field for field: `method: String` ↔ `"symlink" | "package" | "installer" | "manual"`; `on_path: bool` ↔ `boolean`; `resolved_path: Option<String>` ↔ `string | null`; `manual_command: Option<String>` ↔ `string | null`.

| `method` | When | `on_path` | `resolved_path` | `manual_command` |
|---|---|---|---|---|
| `symlink` | macOS | `garita`, found on the process PATH (after `fix_path`) or in `/usr/local/bin`, canonicalises to the canonical `current_exe()` | the entry found, if any | Always set. `sudo ln -s "<exe>" /usr/local/bin/garita`. Prefixed with `sudo mkdir -p /usr/local/bin && ` when the directory is absent. Uses `ln -sf` only when the existing entry is a symlink. |
| `package` | Linux, `APPIMAGE` unset | `garita` on PATH canonicalises to `current_exe()` | the entry found | `None` |
| `manual` | Linux, `APPIMAGE` set | `garita` on PATH canonicalises to the canonical `$APPIMAGE` | the entry found | `ln -s "<$APPIMAGE>" ~/.local/bin/garita` |
| `installer` | Windows | Some directory on the HKCU `Environment` `Path`, the HKLM `SYSTEM\CurrentControlSet\Control\Session Manager\Environment` `Path`, or the process PATH contains `garita.exe`. `%VAR%` entries are expanded first. | that file | The folder of `current_exe()` when `on_path` is false, otherwise `None` |

The decision logic is one pure function over (OS, exe, PATH directories, lookup results, `APPIMAGE`), with unit tests. The registry and filesystem reads are thin shims around it. Windows registry access uses `windows-sys`, already a direct target-gated dependency at 0.61: add only the features needed, such as `Win32_System_Registry`. No new crate. Paths in `manual_command` are double-quoted.

`install_cli_command` on macOS:
1. A temporary location is refused (K12).
2. If `/usr/local/bin/garita` is a regular file, or a live symlink whose target does not end in `/Contents/MacOS/garita`, it returns `Err("Failed to install command: /usr/local/bin/garita already exists and is not Garita's link")`.
3. A dangling symlink, or one with a Garita-shaped target, is replaced. If no entry exists, one is created.
4. Permission denied, or `/usr/local/bin` absent, returns `Ok` with `on_path: false` and `manual_command` set.
5. Success returns `Ok` with the fresh status.
6. It never escalates privileges and never shells out.

## 2. Contract

### 2.1 Launch args (Rust ↔ TS)

```rust
#[derive(Serialize, Deserialize, Debug, Clone, Default, PartialEq)]
pub struct LaunchArgs {
    pub context: Option<String>,
    pub namespace: Option<String>,
    pub kind: Option<String>,     // normalised Watchtower kind; None if absent or unrecognised
    pub ignored: Vec<String>,     // tokens that were not understood, for the toast
}
pub enum LaunchAction { Run(LaunchArgs), PrintHelp, PrintVersion }
pub fn parse_launch_args(argv: &[String]) -> LaunchAction; // pure, tested; never panics; argv[0] skipped
pub const CLI_COMMAND_NAME: &str = "watchtower";
```

| Rust (app-local, no `context`) | invoke / event |
|---|---|
| `get_launch_args() -> Result<LaunchArgs, String>` (the first instance's own argv, consumed once) | `invoke<LaunchArgs>("get_launch_args")` |
| event `launch-args` (payload `LaunchArgs`) on a second invocation | `listen<LaunchArgs>("launch-args", …)` registered once in `App.tsx` through a `useResources.ts` helper |

Note on the log-stream rule ("no global `listen`"): that rule is about per-invocation log channels. `launch-args` is an app-level event with one listener for the app's lifetime; R5 records the distinction.

### 2.2 CLI status (Rust ↔ TS)

```rust
#[derive(Serialize, Deserialize, Debug, Clone)]
pub struct CliStatus {
    pub method: String,                 // "symlink" (macOS) | "package" (deb/rpm) | "installer" (Windows) | "manual" (AppImage)
    pub on_path: bool,                  // CLI_COMMAND_NAME resolves on PATH to this app's binary
    pub resolved_path: Option<String>,
    pub manual_command: Option<String>, // macOS: the exact `sudo ln -s …` line; AppImage: a suggested alias line
}
```

| Rust (app-local) | invoke |
|---|---|
| `get_cli_status() -> Result<CliStatus, String>` | `invoke<CliStatus>("get_cli_status")` |
| `install_cli_command() -> Result<CliStatus, String>` (macOS only; elsewhere `Err("Failed to install command: not supported on this platform")`) | `invoke<CliStatus>("install_cli_command")` |

`install_cli_command` never escalates privileges. Permission denied → `Ok` with `on_path: false` and `manual_command` set. An existing `/usr/local/bin/watchtower` that is not our symlink is **not** overwritten: `Err("Failed to install command: /usr/local/bin/watchtower already exists and is not Watchtower's link")`.

### 2.3 TypeScript

```ts
export interface LaunchArgs { context: string | null; namespace: string | null; kind: string | null; ignored: string[]; }
export interface CliStatus { method: "symlink" | "package" | "installer" | "manual"; on_path: boolean; resolved_path: string | null; manual_command: string | null; }
```
