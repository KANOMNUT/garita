**Rust structs (additive)**

```rust
// src-tauri/src/commands/context.rs
pub struct KubeContext {
    // existing: name, cluster, user, is_kubeconfig_default, source, shadowed_sources, server
    /// v2.1.2: `display_proxy` of the proxy-url of the cluster entry this context references.
    /// `scheme://host[:port]`, userinfo, path and query dropped. None = no proxy-url, or unparsable.
    pub proxy: Option<String>,
}

// src-tauri/src/commands/cluster_info.rs
pub struct ClusterAccess {
    // existing: state, message, server_version
    /// v2.1.2: the context's cluster entry has a non-empty proxy-url. Env vars never count (T51-7).
    pub via_proxy: bool,

```

**TypeScript (`src/types/k8s.ts`)**

```ts
export interface KubeContext   { /* existing */ proxy: string | null; }   // v2.1.2: display_proxy output; never contains userinfo
export interface ClusterAccess { /* existing */ via_proxy: boolean; }     // v2.1.2: the context's cluster entry has a proxy-url
```

**Pure Rust helpers** in `commands/context.rs`, beside `server_for_cluster`, each with tests:

| Function | Returns | Tests |
|---|---|---|
| `proxy_for_cluster(clusters: &[NamedCluster], cluster: &str) -> Option<String>` | The raw `proxy-url` of cluster entry `cluster`, first match wins (a twin of `server_for_cluster`; `list_contexts` uses it). `None` when missing or empty. | found; missing cluster; empty string; first wins |
| `proxy_url_for_context(kc: &Kubeconfig, context: &str) -> Option<String>` | Resolves the context's cluster name (first match), then `proxy_for_cluster`. Used by `client_for_context` and `check_cluster_access`. | missing context; delegates |
| `display_proxy(raw: &str) -> Option<String>` | `scheme://host[:port]`. Drops userinfo, path and query; keeps IPv6 brackets; no invented port. `None` when unparsable or hostless. | http, https, socks5, socks5h, with userinfo (output has no `@`), IPv6 `[::1]:3128`, no port, path and query, garbage |
| `effective_proxy(raw: Option<&str>) -> Result<Option<http::Uri>, String>` | What `client_for_context` puts in `Config.proxy_url`. `None` → `Ok(None)`. `http` → as is (userinfo kept: hyper-http-proxy sends it as Basic). `socks5` → as is. `socks5h` → same URI with scheme `socks5`. SOCKS5 with userinfo → `Err`. `https`, any other scheme, no scheme, unparsable → `Err`. | every arm; no `Err` string contains `@` or the host |

`Err` copy (user-facing; reaches every command's error and the trust banner; names the scheme at most, never the host or userinfo):

- Unsupported scheme: `This proxy type isn't supported: {scheme}. Supported types: http, socks5.` (UX-05 §11)
- SOCKS5 with credentials: `SOCKS5 proxies with a user name and password aren't supported yet. Remove them from the proxy-url, or use an http proxy.`
- No scheme or unparsable: `The proxy-url in your kubeconfig isn't a valid URL. Use http://host:port or socks5://host:port.`

**`client_for_context` (`commands/utils.rs`): the whole diff**

```rust
let proxy = super::context::effective_proxy(
    super::context::proxy_url_for_context(&kubeconfig, context).as_deref(),
).map_err(anyhow::Error::msg)?;                       // before kubeconfig is moved
let mut config = Config::from_custom_kubeconfig(kubeconfig, &options).await?;
config.proxy_url = proxy;                             // T51-7: never kube 0.95's env fallback
```

**`check_cluster_access`:** every `Ok(ClusterAccess)` it returns has `message = app_log::scrub(&message)` and `via_proxy = proxy_url_for_context(&merged, context).is_some()`, applied once (in the wrapper, or in the classifier on the `merged` it already loads; rust-engineer's choice), not in each of the struct literals.

**`app_log::scrub` gains URL userinfo:** `scheme://userinfo@host` → `scheme://<redacted>@host`. Userinfo = the text after `://` up to the **last** `@` before the first `/`, `?`, `#`, whitespace or end of input (an unencoded `@` in a password must not leak its tail). Char-based like the existing rules, no regex crate, idempotent, safe on truncated input. Plain `user@example.com` (no `://`) is untouched.

**Frontend helper** `src/utils/proxyLabel.ts` with `proxyLabel.test.ts` beside it:

```ts
export function proxyLabel(proxy: string | null | undefined):
  { label: string; host: string; port: string | null; title: string } | null;
```

- `label`: `via SOCKS5 proxy` for `socks5` and `socks5h`, else `via proxy`.
- `host` keeps IPv6 brackets. Split on the last `:` after a closing `]`. `port` is `null` when absent.
- `null` for null, undefined, empty, any value containing `@`, or no `://`.
- `title`: `Requests to this cluster go through {scheme}://{host[:port]} (proxy-url in the kubeconfig cluster entry)`.
- Tests: null, http, https, socks5, socks5h, `[::1]:3128`, long host, no port, and a value containing userinfo, which must return null. Build that value at runtime (§0.8).

### 0.2 Q51-1 verdict: no kube upgrade

kube 0.95 supports `http` proxies (with Basic credentials taken from the URL) and `socks5` proxies (no credentials, DNS resolved by the proxy) behind two features, and nothing else. Evidence, paths under `~/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/`:

| Claim | Evidence |
|---|---|
| The `kube` facade re-exports both features | `kube-0.95.0/Cargo.toml:142` `http-proxy = ["kube-client/http-proxy", "client"]`; `:168` `socks5 = ["kube-client/socks5", "client"]`; default is `client` + `rustls-tls` (`:130`). |
| They map to two optional crates, both on rustls | `kube-client-0.95.0/Cargo.toml:330` `http-proxy = ["hyper-http-proxy"]`; `:354` `socks5 = ["hyper-socks2"]`; both deps `default-features = false` (`:116-119`, `:138-141`); `rustls-tls` (`:348-353`) enables `hyper-http-proxy?/rustls-tls-native-roots`. |
| Only the exact schemes `socks5` and `http` are wired | `kube-client-0.95.0/src/client/builder.rs:94-115`: `socks5` arm `:96`; `http` arm `:107` (`Proxy::new` + `from_proxy_unsecured`); everything else goes to `_ =>` at `:114`, a direct connector. |
| With the features off there is **no** "proxy protocol disabled" error. Today every proxy-url is silently ignored. | Same `_ =>` arm. The disabled and unsupported errors exist only in later kube (`kube-client-4.2.0/src/client/builder.rs:140-189`, `src/error.rs:32-38`). |
| `https://` (TLS to the proxy) and `socks5h://` are silently direct | They fall to `_ =>`. Hence T51-8. |
| SOCKS5 credentials are never sent | `builder.rs:99` `auth: None` |
| HTTP credentials are sent | `hyper-http-proxy-1.1.0/src/lib.rs:195-205`: `Proxy::new` → `extract_user_pass` (`:528-535`, no percent-decoding) → `Proxy-Authorization: Basic` on the CONNECT (`:210-222`, `Intercept::All`). |
| SOCKS5 resolves DNS at the proxy | `hyper-socks2-0.9.1/src/lib.rs:160` `AddrKind::Domain(host, port)`. So `socks5h` → `socks5` is behaviour-preserving. |
| **Env fallback** | `kube-client-0.95.0/src/config/file_loader.rs:116-131`: when the cluster's proxy-url is empty, kube reads `HTTP_PROXY`, `http_proxy`, `HTTPS_PROXY`, `https_proxy` in that order. It never reads `NO_PROXY`, and `HTTP_PROXY` wins even for https servers. Called from `config/mod.rs:323`. Harmless today (`_ =>` drops it). With the features on, it would proxy every cluster for anyone with an env proxy. Hence T51-7. |
| Proxy URIs do not reach error text | hyper-http-proxy errors are `io_err` wrappers (`lib.rs:138`). Its only formatted error is `tunnel.rs:120-124`, `unsuccessful tunnel (<first 16 bytes of the proxy reply>)`. hyper-socks2 errors are `#[error("{0}")]` wrappers. |

Dependency effect, measured with `cargo tree --locked -e normal --target all` on a scratch copy of `src-tauri/Cargo.toml` + `Cargo.lock` with the two features. That command needs no linker.

- `src-tauri/Cargo.lock` gains exactly two packages, `async-socks5 0.6.0` and `hyper-socks2 0.9.1`, plus `hyper-socks2` in `kube-client`'s list. `hyper-http-proxy 1.1.0` is already in the lock (a weak-feature entry) and becomes compiled.
- Newly compiled: `async-socks5`, `headers 0.4.1`, `headers-core 0.3.0`, `httpdate 1.0.3`, `hyper-http-proxy`, `hyper-socks2`, plus second versions of `openssl-probe` (0.1.6), `rustls-native-certs` (0.7.3) and `security-framework` (2.11.1, macOS only).
- **TLS stays rustls.** No `openssl`, `native-tls` or `hyper-tls` on any of the four `deny.toml` targets. `openssl-probe` only locates certificate paths; it is not OpenSSL, and 0.2.1 is already in the graph.
- Licences: MIT, `Apache-2.0 OR MIT`, `MIT OR Apache-2.0`, `Apache-2.0 OR ISC OR MIT`, `MIT/Apache-2.0` (the slash form is already in the graph and passes CI's cargo-deny). All are in `deny.toml` `allow`. Bans: three duplicate majors, and `multiple-versions = "warn"` does not fail on them. Sources: crates.io only.
- Advisories: none for these crates in the local RustSec DB (fetched 2026-10-09). `security-framework` has only RUSTSEC-2017-0003, patched in ≥ 0.1.12. `cargo deny` is not installed locally; CI's cargo-deny job is the gate once Actions minutes return.

Upgrade path, not in this release: `https://` proxies and SOCKS5 credentials arrive with a kube upgrade. kube-client 4.2.0 has an `https` arm, Basic auth on the tunnel, and explicit unsupported/disabled errors. Its errors may format the proxy URL, so T51-9's scrub is already in place when that happens.

### 0.3 Decisions

| # | Decision | Value | Reason |
|---|---|---|---|
| T51-1 | Mechanism | kube's own proxy support: `http-proxy` + `socks5` features. No hand-rolled connector. | Highest-risk path |
| T51-2 | Provenance | `KubeContext.proxy = proxy_for_cluster(..).and_then(\|p\| display_proxy(&p))` | UX-05: "via proxy <host>"; credentials never shown |
| T51-3 | Failure classification | `ClusterAccess.via_proxy: bool`; states unchanged. A proxy-url rejected by T51-8 fails the client build and lands in the existing `auth` arm with the T51-8 message. That is a known wart: the state set is frozen, and the message says what is wrong. | No new state |
| T51-4 | Harness shape | `#[cfg(test)] mod live` in the lib. Every test is `#[ignore]` and returns early unless `GARITA_LIVE_CONTEXT` is set. | An integration-test crate could not reach the private `commands` module |
| T51-5 | Harness config dir (**revised: no initialiser**) | `CONFIG_DIR` is never set under `cargo test`, because `init_config_dir` needs an `AppHandle`. `load_registry` returns an empty registry when it is unset (`kubeconfig.rs:68-71`), so the harness reads only `KUBECONFIG`. Ledger rows that need the app config or log dir are recorded as not coverable. | The developer's registry is never read, at zero code |
| T51-6 | Harness writes | Only inside namespaces the harness creates (`garita-live-<random>`), deleted at the end; cluster-scoped writes only on objects it created. Refuses to run unless the context name starts with `kind-` or `k3d-`, or `GARITA_LIVE_ALLOW_ANY=1` is set. | Pointed at the wrong context, it must not damage it |
| T51-7 | **Env proxies stay ignored** (new) | `client_for_context` overwrites `config.proxy_url` with `effective_proxy` (kubeconfig only). Known edge: an env proxy value that `http::Uri` cannot parse still fails inside `from_custom_kubeconfig` before the override (this is pre-existing; open item). | §1.2; kube 0.95 ignores `NO_PROXY` (§0.2) |
| T51-8 | **Fail closed** (new) | A proxy-url kube 0.95 cannot honour (`https`, SOCKS5 with userinfo, any other scheme, no scheme) makes `client_for_context` return `Err` with the §0.1 copy. `socks5h` is rewritten to `socks5`. Cost: a context whose `https` proxy-url "works" today, by connecting directly, now fails with that message. CHANGELOG "Changed". | A configured proxy that is silently bypassed sends traffic where the user said it must not go; later kube also rejects |
| T51-9 | **Banner scrub** (new; UX-11 C1, scope widened) | `check_cluster_access` scrubs `message` on every state, not only when `via_proxy`; `scrub` gains URL userinfo. No wider scrub of other command errors: the proxy crates never format the URI (§0.2), and T51-8's copy never includes it. | The banner is a display surface; defence in depth at the backend |
| T51-10 | **Harness proxy discrimination** (new) | The proxied kubeconfigs come from `kind get kubeconfig --internal`. Their server is `https://<cluster>-control-plane:6443`, a name only the `kind` Docker network resolves. The squid and SOCKS5 containers join the `kind` network and publish on `127.0.0.1`, so a bypass fails on DNS. Negative control: the internal kubeconfig *without* proxy-url must be `unreachable`. Squid's config allows CONNECT to 6443 (its default allows 443 only) and keeps the access log. If the internal name fails TLS, R2 stops and reports; never `insecure-skip-tls-verify`. | Against a `127.0.0.1` server, a silent bypass would pass every proxy test |
| T51-11 | **No CI job in v2.1.2** (new; answers Q51-2 and Q51-3) | The harness runs on a developer machine. After U2: a separate `.github/workflows/live.yml`, `on: workflow_dispatch` only, `ci.yml` untouched so `CI OK` is unaffected, actions pinned to SHAs, passing actionlint and zizmor. Recorded as an open item. | Actions are out of quota and the repo is private until U2; a workflow nobody can run is untested code |
| T51-12 | **Banner host** (new; UX-11 C2) | The banner takes `{host:port}` from the active context's `KubeContext.proxy` (`App.tsx` already has `contexts` and `currentContext`). When that is null: "through the proxy". No host in `message`. | The UI styles and truncates the host |
| T51-13 | **`make live`** (new) | `make live` runs `scripts/live/run.sh` through the existing `RUN` macro (MSVC env on Windows), invoking the Makefile's pinned Git Bash (`$(SHELL)`, quoted), never a bare `bash`. `run.sh` runs as-is on macOS and Linux. | Reuse the Windows toolchain guard |

### 0.8 Repo rules this release must keep

- **TruffleHog scans every added line** (`security.yml` → Secret scan, `--results=verified,unknown`). No file may contain a literal URL that has a user name *and* password in its userinfo: not code, tests, fixtures, docs or `CHANGELOG.md`. Tests and `run.sh` build such strings at runtime, e.g. `["http", "://", "user", ":", "pw", "@proxy:3128"].concat()`. Self-check before each commit, over the changed files: `grep -nE '[a-z0-9+.-]+://[^ /@]+:[^ /@]+@' <files>` returns nothing.
- **Userinfo never leaves the backend** and is never logged. It never appears in a `KubeContext`, a `ClusterAccess.message`, an error string or a log line (CLAUDE.md; `app_log` scrubs centrally, T51-9 adds the banner).
- `grep -rn "Patch::Strategic" src-tauri/src` returns exactly one hit (CI checks it).
- Every new Tauri param is `Option<T>` (none in this release).
- `client_for_context` stays the only client construction site: `grep -rn "from_custom_kubeconfig\|Client::try_from" src-tauri/src` hits `utils.rs` only.
- Docs and `CHANGELOG.md` `[Unreleased]` change in the same commit as the behaviour (each task adds its own lines; F2 only renames the heading).

## Ground rules

As `v1.4.0-tasks.md`, with these deltas:

- **Cargo feature change sanctioned**: the rust-engineer adds the two kube features (§0.2). No new direct crates.
- **Treat any auth regression report as pointing here first** (`docs/claude/cluster-access.md`).
- Proxy URLs can carry a user name and password. **Userinfo never leaves the backend** and never reaches a log line (§0.8).
- No app-level proxy settings screen (UX-05 hard constraint). `proxy-url` is read from the kubeconfig only.
- No CI job in this release (T51-11).

## 7. Risks

| Risk | Mitigation |
|---|---|
| The feature flags change TLS or connector behaviour for non-proxied clusters | `effective_proxy` returns `None` for them, so the builder takes the same `_ =>` arm as today (`builder.rs:114`). The harness runs the full suite without a proxy too; any difference is a release blocker. |
| T51-8 breaks a context whose `https` proxy-url works today by connecting directly | Clear message; CHANGELOG "Changed"; U-C can override |
| A silent proxy bypass passes the tests | T51-10 internal server name + negative control |
| The harness damages a real cluster | T51-6 gate, owned namespaces only |
| Credentials committed in a fixture or test | §0.8 runtime construction + self-grep; TruffleHog in CI |
