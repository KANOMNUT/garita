**Ground rules**

As `v1.4.0-tasks.md`, plus:

- **React Query stays the only state layer.** Watch events are written into the query cache with `queryClient.setQueryData`; there is no second store, no event bus, no global `listen`.
- **Polling is always the fallback.** A watch that cannot start, or dies, returns the view to its v1.7.0 polling behaviour without user action.
- **#38 and #39 commits never touch a file the rebrand plan owns**, and the rebrand commits never touch #38/#39 logic. Where both must edit one file (for example `README.md`), the rebrand group lands first and the feature group rebases on it.
- **No cross-cluster bulk write.** Every write keeps acting on exactly one context, shown in its confirm (`contextLabel`/`contextColor` from that row's context).

#### A3. Persisted state across the identifier change (Q200-1, RB-3b)

**Finding (blocker for option A).** `readOnly`, `typedConfirm` and `bulkLimit` live only in the webview's `localStorage["cluster-identity"]` (`src/utils/clusterIdentity.ts`, `STORAGE_KEY`). A new identifier means a new, empty webview store, and every guardrail then reads as off. `active-context` resets as well, so v2 opens on the kubeconfig default context, which may be production. Option A therefore turns read-only protection off on production clusters with no warning. It is rejected.

**D contract (frozen).**

Rust, `src-tauri/src/commands/migrate.rs` (rust-engineer), registered in `lib.rs`. App-local, so it takes no `context`:

```rust
#[tauri::command]
pub async fn detect_legacy_install(app: tauri::AppHandle) -> Result<bool, String>
// Ok(true) iff legacy_dir(app_config_dir) is a directory AND differs from app_config_dir.
// Err only when app_config_dir cannot be resolved: format!("Failed to resolve app config dir: {}", e)
```

| Rust param | JS arg |
|---|---|
| (none; `app` is injected) | (none): `invoke<boolean>("detect_legacy_install")` |

- The signal is "the legacy **config dir exists**", **not** "a registry was migrated". `init_config_dir` creates that dir on every launch. `git log -S` shows that `create_dir_all` and `"cluster-identity"` both arrived in `478b1f5` (v1.2.0), so every install that could have stored identity or guardrails has the dir. A v1 user with only `~/.kube/config` has no `kubeconfigs.json`, so RB-3a does nothing for them, yet they may have guardrails set.
- It reuses `legacy_dir()`. Test cases: same dir → `false`; sibling present → `true`; sibling absent → `false`.
- It is a read and not a write command, so it does not go through `invokeWrite`.

Frontend (frontend-engineer):

- `useResources.ts`: `detectLegacyInstall()` is the only `invoke` site.
- `clusterIdentity.ts`: a pure `seedReadOnly(contexts: string[]): Record<string, { readOnly: true }>` with a test, plus a writer that writes **only if `localStorage["cluster-identity"]` is still `null`**, checked again just before the write. That check is what makes it run once. The writer then calls the module's `notify()`, as `setClusterIdentity` does.

### Facts found while planning

These shape the plan. Several contradict assumptions in the original request, so they are listed first.

1. **The git history is not a single squash.** `a5dad3e feat: init` (2026-10-03) is a large diff on top of the earlier v0.x to v1.2.1 history, not a fresh root.
2. **There is an explicit proprietary notice today.** `README.md:185` and `public/index.html:719` both carry an all-rights-reserved copyright line. There is no `LICENSE`, `NOTICE` or `COPYING` file. `package.json` is `"private": true` and has no `license` field. `Cargo.toml` has no `license` field and `authors = ["Watchtower"]`.
3. **Leftover names from earlier brands.** The Vite shell `index.html` has `<title>Kube View</title>` and `<link rel="icon" href="/vite.svg">`, and `vite.svg` does not exist. `capabilities/default.json` (and the generated `gen/schemas/capabilities.json`) say "K8s Manager". The Rust lib crate is `my_k8s_app_lib`. The agent files hard-code an absolute local checkout path.
4. **The bundle identifier `com.watchtower.app` is itself a problem.** It ends in `.app`, which the Tauri CLI warns against on macOS because it collides with the bundle extension. It is also reverse-DNS for `watchtower.com`, a domain the project does not control. Changing it is right regardless of the rename, but it is a new app identity (see RB-3).
5. **App-owned kubeconfigs live inside the identifier-keyed directory.** Pasted-YAML imports are written to `<app_config_dir>/kubeconfigs/<name>.yaml` (`kubeconfig.rs:400`), and the registry `<app_config_dir>/kubeconfigs.json` stores their **absolute paths** (`app_owned: true`). A naive copy of the registry to the new directory would keep pointing at the old directory, which then works only until someone deletes it. The migration must copy those files and rewrite the paths.
6. **The product name is written into cluster objects.** ArgoCD sync and rollback set `operation.initiatedBy.username = "watchtower"` (`argocd.rs:871`, `:1294`, asserted in a test at `:1412`). It shows in ArgoCD's operation history. After the rename, new operations will show `<newname>` while old history keeps `watchtower`. This is acceptable but must be in the release notes.
7. **Icons are inconsistent today.** `icon.ico` holds two entries, 32px and a "256" entry whose PNG is actually 128×128. `icon.icns` was hand-made. `src-tauri/icons/AppIcon.iconset/` is referenced by nothing in the build. `src/assets/app-icon.png` (the Sidebar logo) is a byte-for-byte copy of the 32×32 bundle icon, so it is blurry on Retina.
8. **The Homebrew tap is the GitLab repo itself and is SAML-walled.** `brew tap` clones the GitLab project. Existing Homebrew users can only be migrated by a commit to **that** repo, which needs write access to it (see RB-8).
9. "seven" grep hits in `src/` and `src-tauri/src/` are all false positives (`K8sEvent`, `FocusEvent`, the `SEVEN_DAYS_MS` mention in an old plan, "seven characters" in `CHANGELOG.md`). The real old-organisation hits are listed in the inventory.

### RB-3 Data migration for existing users

Changing `identifier` moves every per-app directory. Tauri resolves these from the identifier:

| Data | macOS | Linux | Windows |
|---|---|---|---|
| `app_config_dir` (`kubeconfigs.json`, `kubeconfigs/*.yaml`) | `~/Library/Application Support/<id>/` | `$XDG_CONFIG_HOME/<id>/` (`~/.config/<id>/`) | `%APPDATA%\<id>\` |
| Webview storage (`localStorage`) | WebKit data store for the app (verify exact path on a real install) | `~/.local/share/<id>/` (WebKitGTK, verify) | `%LOCALAPPDATA%\<id>\EBWebView\` (verify) |
| `app_log_dir` (only if v1.3.1 #46 app log file has shipped) | `~/Library/Logs/<id>/` | `~/.local/share/<id>/logs/` (verify) | `%LOCALAPPDATA%\<id>\logs\` (verify) |

**Without a migration, a v2.0.0 user loses:** every imported kubeconfig (registered paths and pasted-YAML imports), enable/disable state, the active context, cluster identity colours and labels, column visibility, panel widths, log viewer preferences, the neat-YAML toggle and the ArgoCD grouped/flat view. Their `~/.kube/config` and any kubeconfig files on disk are untouched in every case.

#### RB-3a Registry migration (Rust, required)

Runs once in `lib.rs` `.setup()`, **before** `commands::kubeconfig::init_config_dir`. New module `src-tauri/src/commands/migrate.rs`.

- `const LEGACY_IDENTIFIER: &str = "com.watchtower.app";`
- `legacy_dir = new_config_dir.parent()?.join(LEGACY_IDENTIFIER)`. The identifier is the last path component on all three OSes, so the sibling lookup is portable. It is a pure function: unit-test it with `PathBuf`s.
- Migrate only if the new `kubeconfigs.json` does **not** exist and the legacy one **does**. An existing new registry always wins, so the migration never runs twice and never overwrites.
- Copy `legacy/kubeconfigs/*.yaml` to `new/kubeconfigs/`, then load the legacy registry and, for each entry with `app_owned: true` whose `path` starts with the legacy directory, rewrite the prefix to the new directory. Entries with `app_owned: false` are user files. Copy their paths verbatim and never touch the files.
- Write the new registry last, so a crash mid-copy leaves no new registry and the next launch retries.
- **Never delete or modify the legacy directory.** A v1.x install may still be running side by side (RB-4).
- Failures are logged and swallowed. A failed migration degrades to an empty registry, which is the same as a first run and matches how `load_registry` already treats a corrupt file. Startup must not fail.
- Call `invalidate_client_cache()` after a successful migration (hard rule: every registry mutation does).
- `cargo test --lib` cases: prefix rewrite for app-owned entries, user entries untouched, no-op when the new registry exists, no-op when the legacy one is missing, corrupt legacy JSON gives no new registry and no panic.

## 2. Proposed IPC contract (#38, #39)

### 2.1 Watch (`commands/watch.rs`)

| | |
|---|---|
| Rust | `pub async fn start_watch(app: AppHandle, state: State<'_, WatchRegistry>, context: String, kind: String, namespace: String, on_event: Channel<WatchEvent>) -> Result<String, String>` |
| invoke | `startWatch` in `useResources.ts` → `invoke<string>("start_watch", { context, kind, namespace, onEvent })` |
| Rust | `pub async fn stop_watch(state: State<'_, WatchRegistry>, watch_id: String) -> Result<(), String>` (app-local: no `context`; stopping an unknown id is `Ok`) |
| invoke | `invoke("stop_watch", { watchId })` |

```rust
#[derive(Serialize, Clone)]
#[serde(tag = "event", rename_all = "snake_case")]
pub enum WatchEvent {
    Snapshot { items: Vec<serde_json::Value> },   // each item = the SAME converted row the list command returns
    Applied { item: serde_json::Value },
    Deleted { key: String },                      // "<namespace>/<name>" ("/<name>" for cluster-scoped)
    Status { state: String /* "live" | "reconnecting" | "stopped" */, message: String },
}
```

- Items are produced by the **same conversion function** the kind's list command uses (`convert_pod`, …), so a watched row and a polled row are byte-identical. Acceptance: a test per watchable kind asserting the list command and the watch use one converter.
- `namespace == "all"` or `""` → `Api::all`; otherwise namespaced. The Services all-namespaces fallback is not relevant (Services are not watchable in v2.0.0).
- Errors: unsupported kind → `Err("Failed to start watch: unsupported kind '{k}'")`; client → `Failed to connect: {e}`. Watcher stream errors become `Status { "reconnecting", msg }` while kube's backoff retries; after 5 consecutive failures without a successful event the task ends with `Status { "stopped", msg }`, and the frontend falls back to polling.
- Pure, tested: `row_key(kind, &Value)`, the event mapping from `watcher::Event` to `WatchEvent` (with `Init`/`InitApply`/`InitDone` buffered into one `Snapshot`).

### 2.2 Frontend watch hook (`useResources.ts`)

`useWatchedList(kind, context, namespace, queryKey)`:
- starts on mount, stops on cleanup (T200-4);
- `Snapshot` → `setQueryData(queryKey, items)`; `Applied` → upsert by `row_key`; `Deleted` → remove by key;
- while `live`, the matching list query's `refetchInterval` is `false`; on `stopped` or start failure it is restored;
- exposes `liveState: "live" | "reconnecting" | "polling"` for the TopBar indicator (UX-06), with reduced-motion-safe "row changed" highlighting.

Pure, tested `src/utils/watchCache.ts` (upsert/remove by key, snapshot replace, order preserved by name).

### 2.3 Multi-cluster (#39)

- `localStorage["active-context-set"]`: `string[]`, at most 6 (T200-7), validated against `list_contexts()` on load like `useActiveContext`; invalid entries dropped.
- Multi-cluster mode applies to `pods`, `deploy`, `sts`, `ds`, `svc`, `nodes`, `events`, `helm`, `argocd` (kinds whose rows already carry namespace + name). Other views show a notice and use the primary context.
- Rows gain a client-side `context` field (never sent to the backend); the cluster column renders the identity chip (role + label, never colour alone); sort is merged.
- Per-cluster state strip: each context's `check_cluster_access` state and query state; one failing cluster degrades only its rows (UX-06).
- Opening a row opens the detail panel **with that row's context**; every write in the panel uses it; ConfirmModal gets that context's label/colour.
- **R2 (small):** none required by the data layer; R2 is only a review that no list command reads global state that assumes one active context (expected: none). If one does, stop and report.

```ts
export type WatchEvent =

  | { event: "deleted"; key: string } | { event: "status"; state: "live" | "reconnecting" | "stopped"; message: string };
```

`watch` module; `WatchRegistry` managed state; register `start_watch`, `stop_watch`. Capabilities: none expected (channels already used by log streams).
