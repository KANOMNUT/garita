## 0. Minimal version, and what it skips

The release, with the user's answers:

- **Sidebar.** The "Custom Resources" section (one expandable row per API group, one row per CRD kind) is removed, the way v2.4.0 removed the namespace list. The existing **CRDs** row of the "Cluster" section is the entry and stays highlighted while a CRD's objects are shown. No new Sidebar row.
- **CRDs page.** CRDs sit under collapsible API-group header rows (group name and count, all expanded on open, Kind A-Z inside each group). A "Group by API group" switch, on by default and remembered on this computer, gives today's flat list back. Each row gets an **Instances** button; the CRD panel's Overview gets a **Show instances** link. Both open the existing objects list, which gains an **All CRDs** link back. Row click still opens the CRD panel.
- **Custom resource panel (new).** Clicking an object opens a panel with Overview (kind, API version, namespace, age, phase, generation, owners, finalizers, deletion), Summary (conditions with only `Ready` coloured, labels, annotations, "Managed by" ArgoCD app), Events and YAML (Neat, Find, Copy). **Writes:** YAML **Edit** with **Review & save…** through the existing Review and save gate (server dry run first), and **Delete** from the panel header and from the list row (one shared confirm, Background propagation, journal entry). Both are disabled with a reason in read-only mode or on an explicit RBAC denial.
- **Rust.** In `crds.rs`, three reads (`get_custom_resource`, `get_custom_resource_yaml`, `get_custom_resource_yaml_neat`) and three writes (`delete_custom_resource`, `preview_custom_resource_yaml`, `apply_custom_resource_yaml`). All take the CRD's group, version, kind, plural and scope flat, like `list_crd_resources`. Each refuses an empty API group. `list_crds` gains `read_version`. The YAML writes go through the **one** replace path in `pods.rs`, which learns a custom resource target (`ReplaceTarget::Custom`). No existing command gains a parameter or changes behaviour, and no per-kind table changes.
- **Frontend plumbing.** One optional `groupBy` on `GenericResourceTable` plus a pure `groupRows`; a pure `src/utils/crds.ts`; read, write and permission hooks in `useResources.ts`; a new `CustomResourcePanel.tsx` and `DeleteCustomResourceConfirm.tsx` hosted by `App.tsx`; `YamlSaveGate` gains an optional custom resource target.
- **Live harness.** One new `#[ignore]` test runs every new command against a built-in API group (a Role in the harness's own namespace), so the custom resource read, preview, save and delete paths meet a real API server without creating a CRD.

Skipped (each is a later request):

- Compare and Field managers for custom resources (excluded by the user's answer to Q3); a guided edit form (no form engine; `writes.md`).
- A propagation picker in the custom resource delete confirm (Background only, sent explicitly); bulk delete.
- A discard confirm for unsaved YAML edits, unless the user answers Q11 with B or C.
- A header status chip, a Status column on the objects list, instance counts per CRD (not chosen: Q4 C, Q8 B, Q5 B/C).
- One palette entry per CRD kind, a launcher token for a CRD (Q6 A). `crd-instances` stays unmapped on the command line.
- Clickable owner references; clickable rows in the CRD panel's instance preview; a Timeline or Map for custom resources; arrow-key navigation in the grouped table; persisting which groups are collapsed.
- A live check against a real CRD (conversion webhook, status subresource, schema validation): the harness never writes cluster-scoped objects (`live-verification.md` → Safety, T51-6) and kind ships no CRD. The built-in-group test covers the code path; section 6.3 lists what only a real cluster closes.

## 1. Decisions taken in this plan

| # | Decision | Why |
|---|---|---|
| D1 | The Sidebar keeps its **CRDs** row (Cluster section) as the only entry; it is active on both `crd` and `crd-instances`. | v2.4.0 put Namespaces as a Cluster row. CRDs already is one. The highlight tells the user where they are. |
| D2 | The custom resource panel is a new component, `CustomResourcePanel.tsx`, **not** a `SelectedResource` member. | A custom resource has a runtime group, version and kind. The five silent tables and the `Record<SelectedResource["kind"], …>` tables (`kindLabel`, `EVENT_INVOLVED_KIND`, `isHealthy`) are keyed by a static kind, and `get_resource_yaml` / `delete_resource` have no dynamic arm. Precedent: the Pod panel is its own component (`DetailPanel.tsx`). |
| D3 | Selection state `selectedCr: CustomResourceSelection \| null` in `App.tsx`, apart from `selectedResource` and `selectedPod`. The panel renders only while `activeResource === "crd-instances"` and `selectedCr.crd.name === crdTarget?.name`. Cleared in the `[namespace, activeResource]` effect, the context-switch effect and the Esc branch, and after its object is deleted. | One identity per panel host. The render guard means a stale selection never shows a panel for another CRD. |
| D4 | Every new command takes the CRD fields flat (`group, version, kind, plural, scope`), like `list_crd_resources`. The scope comes from the CRD, never from the namespace value. | Same convention as the existing CRD-instance command; same rule as `get_resource_json`. |
| D5 | `get_custom_resource` returns `Option`: 404 is `Ok(None)`, like `get_pod`. | The panel can say the object is gone instead of showing an error box. |
| D6 | The YAML reads mirror `get_resource_yaml` / `get_resource_yaml_neat` and share `render_obj` (`pods.rs`, made `pub(crate)`) and `NeatYaml`. Neat stays display only; the editor is seeded from the full YAML. | One command per output shape; the same neat rules as every other kind. |
| D7 | Grouping is a generic optional `groupBy` on `GenericResourceTable`, with a pure `groupRows`. | Search, sort, selection, the X-1 row button, the read-only strip, the 403 card, the count badge and the row trash are reused. |
| D8 | The Events tab reuses `get_resource_events` with `kind = crd.kind`. | It already filters `involvedObject.name` and `.kind`, and lists all namespaces for `""`. |
| D9 | Conditions are parsed in Rust, panic-free; first entry per `type` wins; messages go through `operation_message_display` (2000 characters, cut by characters). | `status` is untrusted input and release builds abort on panic. `ConditionsTable` keys rows by type. |
| D10 | `cr_request` refuses an empty API group, and **every** new command, read or write, calls it before connecting. | A CRD always has a group. Without the check a webview-supplied `group: ""`, `plural: "secrets"` could read, replace or delete a core Secret with no reveal, no masking and no Secret rules. |
| D11 | The YAML writes reuse the **one** replace path: `replace_resource_yaml` takes a `ReplaceTarget` (`Kind(&str)` or `Custom { ar, namespaced }`) instead of `&str`. The preview body and the apply body are extracted once (`preview_replace`, `apply_replace`) and called by both the existing commands and the new ones. | Hard rule: one shared replace path in `pods.rs`, so a custom resource preview validates exactly what its save does. A second replace function would be a second path. |
| D12 | The existing `apply_resource_yaml`, `preview_resource_yaml` and `delete_resource` keep their signatures, behaviour and error strings. They are **not** called for custom resources (their `resource_type` matches are per kind); the new commands sit beside them. | One command per shape; no `Option` union on a frozen command; no risk to the 40-odd built-in kinds beyond the mechanical `ReplaceTarget::Kind` wrap. |
| D13 | `ReplaceError::Kube.label` becomes `Cow<'static, str>`: existing arms pass their literal (`Cow::Borrowed`), the custom arm passes the CRD kind (`Cow::Owned`). | The custom label is known only at run time. Existing error text stays byte-identical ("Failed to apply deployment: …"). |
| D14 | `delete_custom_resource` sends Background explicitly through `delete_params_for(None)`; there is no propagation parameter and no picker. | Hard rule: explicit policy. A propagation parameter can be added later as an additive `Option<String>`. |
| D15 | Journal kind for custom resource writes is `"<plural>.<group>"` (for example `widgets.acme.io`), the same noun the kubectl equivalent uses. | Unambiguous across groups; the journal shows an unknown kind verbatim (`journalKind`). |
| D16 | One `DeleteCustomResourceConfirm` is hosted in `App.tsx`; the list's row trash and the panel's header trash request it. | v2.4.0 pattern (`DeleteNamespaceConfirm`): one confirm, one owner of the post-delete reset (the panel closes when its object is deleted). |
| D17 | RBAC hints for custom resource writes come from a new `useCustomResourcePermissions` (`delete` and `update` on `crd.group` / `crd.plural`), with `usePermissions`' fail-open rules. `RBAC_RESOURCE` is not touched. | `usePermissions` is keyed by `ResourceType`. YAML save is a PUT, which is the `update` verb. |
| D18 | No YAML editor in the app asks before discarding an edit today (the resource panel's and the Pod panel's Cancel drop the buffer); the only "Discard changes?" confirm is the Observability dialog's (UX 19). The custom resource editor follows the YAML editors (Q11 A) unless the user picks otherwise. | Consistency between the three YAML tabs. |
| D19 | A live test exercises the six new commands on a **built-in** API group (`rbac.authorization.k8s.io/v1` Role in the test's own namespace). | It passes `cr_request` (non-empty group), runs the `ReplaceTarget::Custom` arm, the dry run, the conflict and the delete on a real API server, and writes only inside a `garita-live-*` namespace (T51-6). |
| D20 | Docs land in task D1 after the code, on this branch, before the release commit. | v2.3.0 (R4) and v2.3.1 (D1) precedent: code agents never share a doc file; D1 greps every claim against merged code. |
| D21 | No `log_read` call in the new read commands. | `diagnostics.md`: Debug read logging covers exactly three commands, "not every read". The writes are logged by `log_write`. |
| D22 | Removing the Sidebar tree also removes its always-mounted `useCRDs` observer. | `["crds", ctx]` is then observed only by the CRDs page and Who can (while visible); the 60 s app-wide CRD poll ends. |

```rust
/// Validates a request before any network call. Returns the ApiResource and the namespace to use
/// (`Some(ns)` for a namespaced CRD, `None` for a cluster-scoped one, whose namespace is ignored).
/// Called first by EVERY command in 2.1 and 2.2. `label` is `kind`, or "custom resource" when `kind` is empty.
/// Errors, exactly:
///   group ""                          -> "Failed to get {label}: a custom resource needs an API group"
///   version / kind / plural / name "" -> "Failed to get {label}: missing {version|kind|plural|name}"
///   scope "Namespaced", namespace ""  -> require_namespace's message: "{kind} is namespace-scoped and requires a namespace"
///   scope not "Namespaced"/"Cluster"  -> "Failed to get {label}: unknown scope '{scope}'"
pub(crate) fn cr_request<'a>(
    group: &str, version: &str, kind: &str, plural: &str,
    scope: &str, namespace: &'a str, name: &str,
) -> Result<(ApiResource, Option<&'a str>), String>;
// Builds the ApiResource with resource_edit::api_resource_for and checks scope with resource_edit::require_namespace
// (both pub(crate) already). The write commands use the same messages: they describe a bad request, not a failed write.

/// `status.conditions` entries that are objects with a non-empty string `type`, in order, first per type wins.
/// `status`: a string verbatim; a bool as "True" / "False"; anything else "Unknown".
/// `reason`, `lastTransitionTime`: strings verbatim, else "". `message`: a string through
/// argocd::operation_message_display (pub(crate) already), else "".
/// [] when `status` is None, not an object, or has no `conditions` array.
fn cr_conditions(status: Option<&serde_json::Value>) -> Vec<ResourceCondition>;

/// The panel shape. `ar` supplies apiVersion and kind when the object's TypeMeta is absent.
fn cr_detail(obj: &DynamicObject, ar: &ApiResource) -> CustomResourceDetail;

/// The journal kind of a custom resource write: "<plural>.<group>".
fn cr_journal_kind(plural: &str, group: &str) -> String;
```

### 2.2 Rust writes (R1)

**`pods.rs`: the one replace path learns a custom target.** Nothing else in the file changes behaviour.

```rust
/// What a YAML replace writes to: a Garita kind string (the per-kind arms, unchanged) or a custom resource,
/// written as a DynamicObject at the CRD's group, version and plural (from `cr_request`, never `kind_to_plural`).
pub(crate) enum ReplaceTarget<'a> {
    Kind(&'a str),
    Custom { ar: &'a ApiResource, namespaced: bool },
}

enum ReplaceError {
    Invalid(String),
    Kube { label: Cow<'static, str>, source: kube::Error }, // was &'static str (D13)
    Unsupported(String),
}

/// THE replace path (signature change: `resource_type: &str` becomes `target: &ReplaceTarget`).
/// `Kind(k)`: the existing `match k { … }` arms, moved unchanged under this arm.
/// `Custom { ar, namespaced }`: Api::namespaced_with(client, namespace, ar) when namespaced, else Api::all_with(client, ar);
///   the YAML parsed as one DynamicObject (serde_yaml::from_str, never the multi-document iterator);
///   api.replace(name, &pp, &obj); typed_live: None (so dropped_paths is []); label = ar.kind.
async fn replace_resource_yaml(
    client: kube::Client, namespace: &str, target: &ReplaceTarget<'_>, name: &str,
    yaml: &str, dry_run: bool, live_raw: Option<&serde_json::Value>,
) -> Result<ReplaceOutput, ReplaceError>;

/// Some(invalid preview) when `yaml` fails the single-document parse. Both preview commands call it before connecting.
pub(crate) fn invalid_yaml_preview(yaml: &str) -> Option<YamlSavePreview>;

/// preview_resource_yaml's body after the kind is resolved: raw live GET (Api<DynamicObject> on `ar`, scoped by
/// `namespaced`), dry-run replace through replace_resource_yaml(target), outcomes ok / invalid / rejected / conflict,
/// Err only for "preview unavailable". Error strings unchanged.
pub(crate) async fn preview_replace(
    client: kube::Client, namespace: &str, target: &ReplaceTarget<'_>,
    ar: &ApiResource, namespaced: bool, name: &str, yaml: &str,
) -> Result<YamlSavePreview, String>;

/// apply_resource_yaml's body: the real replace through replace_resource_yaml(target), mapped with
/// ReplaceError::apply_message. The caller connects and logs.
pub(crate) async fn apply_replace(
    client: kube::Client, namespace: &str, target: &ReplaceTarget<'_>, name: &str, yaml: &str,
) -> Result<(), String>;
```
