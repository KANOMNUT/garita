### A.2 RUST-AFFECTING (relay to rust-engineer)

Own files as in §6. Everything stays read-only. No new crate, no IPC shape change and no new command. Verification as in §4: `cargo check`, `cargo test --lib`, `cargo clippy --all-targets`. On Windows, use the MSVC `PATH` recipe in `CLAUDE.md` and check the `rustc -vV` host first.

**R7. One memory quantity parser (`utils.rs`).**
- Add `pub(crate) fn parse_mem_bytes(s: &str) -> Option<i64>` for the Kubernetes Quantity grammar:
  - binary suffixes `Ki`, `Mi`, `Gi`, `Ti`, `Pi`, `Ei` (2^10 to 2^60);
  - decimal suffixes `k`, `M`, `G`, `T`, `P`, `E` (10^3 to 10^18) and `m` (10^-3);
  - no suffix (bytes);
  - the exponent form (`129e6`, `1E3`; a bare trailing `E` is exa);
  - a decimal mantissa (`1.5Gi`).
- Use `strip_suffix`, never byte slicing. Return `None` for garbage, an empty string, a negative value, a non-finite value or an overflow. It never panics.
- `parse_mem_mib(s)` becomes `parse_mem_bytes(s).map(|b| b / 1_048_576)` (floor). The signature is unchanged, so the `pods.rs` and `workloads.rs` callers stay as they are and become correct.
- Delete `pods::parse_memory_mib` and `nodes::parse_memory_bytes`. Their callers (metrics usage in `pods.rs`; `fetch_node_metrics` and the node percent in `nodes.rs`) use `parse_mem_bytes`/`parse_mem_mib` with `.unwrap_or(0)` where the old function returned 0.
- `capacity.rs`: drop the `parse_memory_mib` fallback. Sum memory per node in **bytes** and convert to MiB once, when building the row. Flooring each container drifts by tens of MiB per node against `kubectl describe node`.
- Tests, as a table:
  - `128Mi` → 128, `1Gi` → 1024, `1G` → 953, `512M` → 488, `1.5Gi` → 1536;
  - `134217728` → 128, `129e6` → 123, `1Ti` → 1048576, `1024Ki` → 1, `1k` → 0;
  - `parse_mem_bytes("1k") == Some(1000)`;
  - `garbage`, `""` and `-1Gi` → `None`.
- Out of scope: the three CPU parsers (`utils::parse_cpu_millis`, `pods::parse_cpu_millis_usage`, `nodes::parse_cpu_millicores`). All three parse the canonical forms the API server returns. R6 delta 4 records them as a follow-up.

**R8. Sidecar-aware effective requests and limits (`capacity.rs`, `pod_effective_requests`).** Replace the `// ponytail:` sidecar shortcut with upstream's rule. It applies per resource, to requests and to limits alike:

```
reqs     = sum(app containers) + sum(every init container with restartPolicy == "Always")
sidecars = 0; peak = 0
for c in init containers, in order:
    if c is a sidecar: sidecars += c;   peak = max(peak, sidecars)
    else:              peak = max(peak, c + sidecars)
effective = max(reqs, peak)
requests  += overhead
limits    += overhead, only for a resource that some container (app or init) declares a limit for
```

- Before merging, check this against `PodRequests`/`PodLimits` in `k8s.io/component-helpers/resource/helpers.go`, not against this wording.
- Memory is in bytes (R7). `Container.restart_policy` exists in k8s-openapi 0.23 with `v1_31`.
- Tests: a sidecar before a larger plain init container; a sidecar after it; a sidecar-only pod (no plain init container); overhead with limits; overhead without limits (limits stay 0). `overhead_is_added` changes: its pod declares no limits, so its limits are `(0, 0)`.

**R9. Node percent of allocatable (`nodes.rs`, `list_nodes`).** The `cpu_percent`/`mem_percent` denominator reads `status.allocatable` instead of `status.capacity`. It is `None` when allocatable is absent. The `cpu_capacity`, `memory_capacity` and `pod_capacity` strings are unchanged.

**R10. `missing-probes` from templates (`problems.rs`).** As A-10. The rule runs over `deploys` and `stss`; a skipped source means the rule does not run for that kind. `pods` no longer feeds it. The evidence is `field("spec.template.spec.containers[<name>].readinessProbe", "absent")`. Remove `owned_by_deploy_or_sts` if nothing else uses it. Tests: the rule fires once per (workload, container); it does not fire when a readiness probe exists; it skips `replicas: 0`; a 3-replica Deployment yields one finding.

**Ground rules for both engineers**

The ground rules of `v1.3.1-tasks.md` (header block) apply unchanged: own-files only (§6), no writing git commands, never stage `src-tauri/gen/schemas/*.json`, every additive or optional Tauri parameter is `Option<T>`, no new crates, the error format, no `unwrap`/`expect`/byte-index slicing on cluster data (`panic = "abort"`), only `src/hooks/useResources.ts` calls `invoke()`, React Query is the only server-state layer.

Additions for this release:

- **Every command in this release is read-only.** No new cluster write path. If a task seems to need one, stop and report it.
- **No new per-kind table.** The Health pages are app views, not `ResourceType` members. None of the five per-kind tables, and none of the sites in `docs/claude/resource-types.md`, gain a row for them.
- **One expiry rule.** Certificate expiry is classified only by `expiryState` in `src/utils/expiry.ts`. The backend reports facts (`not_after`, `not_before`), never a severity for a certificate.
- **Copy qualifiers are mandatory** (UX brief §3 rule 7): "hint" (#13), "may apply" (#14 webhooks), the events-TTL note (#11). No score, no grade, no "smart", no "auto-fix".

Rules (closed set; every rule is a pure function over typed inputs, unit-tested):

| `rule` | Severity | Fires when | Evidence |
|---|---|---|---|
| `crashloop` | critical | a container is waiting with `CrashLoopBackOff` | last terminated reason + exit code; newest `BackOff` event |
| `oom-killed` | critical | a container's last termination reason is `OOMKilled` and restarts > 0 | the field; the container's memory limit |
| `image-pull` | critical | waiting with `ErrImagePull` or `ImagePullBackOff` | waiting message verbatim |
| `init-failing` | critical | an init container is waiting with a back-off reason or terminated non-zero | the field |
| `unschedulable` | critical | Pending and condition `PodScheduled=False` reason `Unschedulable` | condition message; newest `FailedScheduling` event |
| `workload-unavailable` | warning | deploy/sts/ds with ready < desired **and** (`Progressing=False` reason `ProgressDeadlineExceeded`, or `Available=False`) | the condition |
| `job-failed` | warning | Job condition `Failed=True` | condition reason + message |
| `service-no-endpoints` | warning | a Service with a non-empty selector, type not `ExternalName`, and zero ready addresses across its EndpointSlices | selector; EndpointSlice count |
| `pvc-pending` | warning | PVC phase `Pending` for more than 5 minutes | newest `ProvisioningFailed` / `FailedBinding` event |
| `node-not-ready` | critical | cluster-wide scope only: node condition `Ready != True` | the condition |
| `missing-probes` | info | per Q4-3: a Deployment/StatefulSet-owned pod container has no readiness probe | the container name |

## 8. Risks

| Risk | Mitigation |
|---|---|
| `list_problems` is the most expensive read in the app (eight lists) on large clusters | One command, 30 s cadence, only while the Problems page or an explain card is mounted. Live item: measure on the largest available cluster; if it is slow, the fallback is namespace scope by default (a one-line decision, not a contract change). |
| Rule false positives erode trust | Every finding carries its evidence; rules are deterministic and tested; `missing-probes` is `info` and collapsed. |
| `#49` regresses a write path's namespace (a cluster-scoped kind sending a namespace) | F1 lands first with its own tests; `resourceNamespace` behaviour is unchanged by construction (moved, not rewritten). |
| Presence `unknown` on locked-down clusters could hide the "Not installed" answer | `unknown` falls back to today's behaviour plus a subtitle; never worse than v1.3.1. |
| The NodeStrip overlay runs `list_node_capacity` (a second cluster-wide pod list) whenever the Pods view, the landing view, is open | It is progressive and silent on failure. If it is slow on a large cluster, it is the first thing cut: the overlay then reads only a capacity report the Node capacity page has already cached. |
| A-9 changes the Nodes view CPU%/MEM% that users already read | A CHANGELOG "Changed" entry, and a live item comparing with `kubectl top node`. |
| The explain card (A-5) runs a namespace-scoped `list_problems` while a pod or workload panel is open | It runs only for covered kinds, and only while the panel is open. It is namespace-scoped, never cluster-wide. Panels on the same namespace share one cache entry. |
