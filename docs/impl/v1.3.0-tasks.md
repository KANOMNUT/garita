Status: **FROZEN**. This is the brief for two engineers working in parallel: `rust-engineer` and `frontend-engineer`.
Branch: `feat/v1.3.0`. Baseline: v1.2.1 (commit `2893b25`).
Design sources: `docs/ux/00-overview.md` (with the "amended v1.3" items), `docs/ux/02-logs-debug.md`, `docs/ux/03-diffs-write-safety.md` and `docs/feature-recommendations.md` §4 v1.3.
Sibling plan: `docs/impl/v1.3.1-tasks.md`. It is executed **after** v1.3.0 is committed and tagged, and it builds on this file's contract.
Where this file and a UX doc disagree, **this file wins**. Every disagreement is listed in §1.5.

**Ground rules for both engineers**

- Only edit the files you own (§5). If you need something from a file you do not own, the contract in §2 already covers it. If it does not, stop and report it. Do not edit the other engineer's file.
- **Do not run any git command that writes.** That means no `commit`, `checkout`, `restore`, `stash`, `reset` or `add`. Read-only `git status` and `git diff` are allowed. The main session commits and tags.
- **Pre-existing uncommitted changes are not ours. Do not revert or reformat them:** `src-tauri/gen/schemas/desktop-schema.json` and `src-tauri/gen/schemas/windows-schema.json`.
- Every additive or optional Tauri parameter is `Option<T>`. A bare `bool` or `String` errors at runtime with "missing required key", and nothing catches it at compile time. This bug has shipped twice.
- **Rust: no new crates.** `rust-engineer` never edits `src-tauri/Cargo.toml` or `src-tauri/Cargo.lock`. The frontend owns the version bump in both (§5). If a crate turns out to be genuinely needed, stop and report it. A `cargo check` that rewrites the root package's version in `Cargo.lock` to the value the frontend already set is harmless.
- Rust conventions:
  - Commands are `async`, return `Result<T, String>`, and take `context: String` first.
  - Errors use the form `format!("Failed to …: {}", e)`.
  - No `unwrap`, `expect` or byte-index slicing (`s[..n]`) on cluster data or user input. Release builds use `panic = "abort"`.
  - Wherever this file says "verbatim" for a `kube::Error::Api(ae)`, the message slot is `ae.message`, not `e.to_string()`.
- TypeScript conventions:
  - Display Tauri errors with `(e as any)?.message ?? String(e)`.
  - **Only `src/hooks/useResources.ts` calls `invoke()`.** v1.3.0 moves the existing exceptions in (LogViewer, MultiLogViewer, ShellTerminal; see F3). After this release no component calls `invoke`.
  - React Query is the only server-state layer. Local UI run state is fine. `localStorage` is only for per-viewer conveniences, always inside try/catch.

## 1. Scope and decisions

### 1.1 How v1.3 was split, and why

The user decided to ship v1.3 as two releases.

**v1.3.0** contains:
- the test harness, **first**
- **every live bug** the UX audit found
- the features that are lowest-risk and self-contained

**v1.3.1** contains the rest. That means the diff gates, the write-safety layer (read-only mode, guardrails, kubectl equivalents), the debug container, Diagnostics, drain force-delete and the remaining log filters.

The rule I applied when choosing features for v1.3.0: a feature goes in only if all of these hold.
- (a) It needs at most a small, additive Rust change that touches **no new write path**.
- (b) It lives in a surface this release already has to touch for a bug fix, so it adds no new blast radius.
- (c) It is display-only, or a picker on a dialog that is already confirmed.

**Naming rule.**

- Command arguments: Tauri v2 turns a Rust `snake_case` param into a `camelCase` `invoke()` key. Both columns are listed.

### 2.1 `stream_pod_logs`: CHANGED (breaking channel payload) (`pods.rs`)

**This is a breaking change to a documented contract** (CLAUDE.md "Log Streaming"). The channel element type changes from `String` to an event enum. Both callers (LogViewer, MultiLogViewer) are migrated in this release (F3). `on_log` stays the **first** parameter, and per-invocation Channel isolation is unchanged.

| | |
|---|---|
| Rust | `pub async fn stream_pod_logs(on_log: Channel<LogStreamEvent>, context: String, namespace: String, pod: String, container: String, tail_lines: Option<i64>, since_seconds: Option<i64>, timestamps: Option<bool>) -> Result<(), String>` |
| invoke | `invoke("stream_pod_logs", { onLog, context, namespace, pod, container, tailLines, sinceSeconds, timestamps })` |

```rust
#[derive(Serialize, Clone, Debug)]
#[serde(tag = "type", rename_all = "snake_case")]
pub enum LogStreamEvent {
    Line { line: String },     // {"type":"line","line":"..."}
    End,                       // {"type":"end"}        — server closed the stream normally
    Error { message: String }, // {"type":"error","message":"..."} — stream broke mid-way
}
```

Parameters go through a pure, unit-tested `stream_log_params(container, tail_lines, since_seconds, timestamps) -> Result<LogParams, String>` (always `follow: true`):

| Input | Result |
|---|---|
| `tail_lines` None | `tail_lines = Some(200)` (was a hardcoded 50) |
| `tail_lines` Some(n), n ≥ 1 | `Some(min(n, 5000))`. This is the server-side ceiling, equal to the ring buffer. |
| `tail_lines` Some(n), n < 1 | `Err("Failed to stream logs: tail_lines must be at least 1")` |
| `since_seconds` Some(s), s < 1 | `Err("Failed to stream logs: since_seconds must be at least 1")` |
| `timestamps` | `unwrap_or(false)` |

Behaviour:
- **Start failure:** the invoke rejects with `Failed to stream logs: {message}`. `{message}` is `ae.message` for an API error, else `e`.
- **After a successful start**, the spawned task maps:
  - `Some(Ok(line))` → `Line`
  - `Some(Err(e))` → `Error { message: e.to_string() }`, then exits
  - `None` → `End`, then exits
  - a failed `on_log.send` → exits silently. That is the existing termination path: the frontend dropped the channel.
- `End` or `Error` is sent **at most once**, and nothing is sent after it.
